# 플랜트파일럿 구현 완료 인수 기록

2026-09-22. 합의한 제품 구현과 필수 실행 검증을 완료했다. 목표의 15개 완료 기준, 제품 R01~R15와 D01~D11을 기존 실행 증거에 대조하고 마지막으로 남았던 실제 macOS 파일 선택창 표시·취소까지 확인했다. 모델은 **train 99.57% ≥ 90% PASS, 고정 test 60% < 70% FAIL**이며 이 결과를 기능 완료와 구분한다.

## 완료 범위와 실제 증거

- 검사계획 → 가상 생산팀·랙·포인트 → 실제 사진 업로드·AI 판독 → 필요한 수정·재촬영/라벨 후보 → 보수 상태·방법·TA 워크리스트 → 같은 사진과 이력 재조회 흐름을 실제 브라우저·API·DB·객체 파일로 확인했다.
- 묶음 12개와 추가 1개, 28,323,297바이트 유효 이미지의 실제 저장·재조회·추론과 입력/DB/API/MinIO 크기·SHA-256 일치를 확인했다. 부분 실패·응답 손실·새로고침 복구, 같은 ID 유지와 중복 없는 완료도 검사했다.
- 계획별 사진·보수 관계, KPI 이동·전체 수량, 숨김·복원과 늦은 AI 완료 후 숨김 보존, 두 창의 저장 충돌·입력 보존, 워크리스트 등록·해제·재등록과 끝 페이지 접근을 확인했다. 실패 사진의 재요청 버튼 한 번으로 실제 모델 결과가 같은 사진에 연결되는 것도 검증했다.
- 원본 300장은 공유 환경과 분리한 로컬 환경에 300개 기록·299개 고유 객체로 등록했다. 팀별 75장·랙별 25장, 4계획·12가상포인트와 전체 페이지를 확인했다. 원본 재조회·등록 재개·재실행·재시작 후 파일과 기록 보존을 검사했다. 지도 마커 겹침 수정 뒤 PC·모바일 36개 중앙 클릭을 통과했다. 가상 배치를 실제 측량 위치로 표현하지 않는다.
- 마지막 QA는 새 전용 Chrome 창에서 실제 macOS 파일 선택창을 직접 보고 취소했다. 선택 파일 없음·전송 비활성·큐 없음과 전후 API 응답 불변을 확인했다. DB 전후 요약에서 전체 네 테이블의 개수·해시도 같았다. 허브는 API 응답을 별도 정규화해 대조했으며 DB 원행을 직접 다시 해싱하지 않았다. 기존 filechooser·실제 업로드 증거와 이번 native 시각·취소 증거를 구분한다. 파일 선택·새 업로드·추론은 하지 않았고 네트워크 쓰기 요청 개수는 별도 계측하지 않았다. OS 창에서 여러 파일을 고르는 시각 조작은 이번 취소 검사에 포함하지 않는다.

실제 스크린샷과 백엔드 파일·동일 ID 증거를 사용했으며 로그 생성만으로 성공을 판정하지 않았다. 회사 원본 화면과 개인 다운로드 목록을 포함하는 OS 창 증거는 공개하지 않고 로컬에 보존한다. 실제 사용자·동료 검수는 선택 피드백이며 이번 에이전트 검증을 사람 검수로 표시하지 않는다. 상세한 범위·실패·복구는 [요구별 현황](2026-09-22-product-v2-status.md)과 [독립 QA PR #4](https://github.com/junhang-dev/inspection-image-platform/pull/4)의 기록을 따른다. 마지막 QA 문서 커밋은 `55557b8572deed08c03974d032b349421d894443`다.

## 성능 관측과 모델 미달 인계

새 대표 업무 흐름 한 번의 자동 조작은 총 3,969.700ms이며 AI 결과만 기다린 1,297.500ms를 제외하면 업무 조작 2,672.200ms다. 승인 사진 한 장의 관측으로 사람 판단·OS 파일 찾기 시간은 포함하지 않는다. 승인 사진의 동일 바이트 복제 10장은 저장 확인까지 8,814.600ms, 이후 전체 AI 결과 표시까지 6,236.900ms였다. 저장 확인 시 이미 5장이 완료됐으므로 뒤 시간을 10장 순수 모델 연산으로 해석하지 않는다. 배치가 미완료인 동안 계획·캘린더·조회가 가능했고 AI와 겹친 업무 시간을 이중 차감하지 않았다. 모든 환경의 속도 보장은 아니다.

모델 개발에서는 초기 분류기 10개 설정의 실제 fit과 별도 미세조정 12epoch를 수행했다. 미세조정의 초기 epoch 0을 포함한 13회 validation 관측은 13개 독립 학습 실험과 다르다. validation으로 선택한 모델과 전처리를 고정한 뒤 test를 평가하고 같은 모델을 서비스에 연결했다. 모든 가능한 개선을 소진했다거나 10회 연속 정체를 검증했다고 주장하지 않는다.

사용자는 10회 이상 개선 후에도 더 나아지지 않으면 그 선에서 마무리하고 최선 모델을 실제 서비스에 연결하도록 허용했다. 이 성능 미달 인계 경로에 따라 제품 구현 목표를 완료 판정하며, **test 합격 기준 70%와 실제 60% FAIL은 그대로 유지**한다. 연결 성공이 성능 합격은 아니다. 고정 test 재추론·튜닝·샘플 선정·기준 하향이나 모델 자동 교체는 하지 않는다. 자세한 평가와 버전은 [모델 최종 평가](https://github.com/junhang-dev/inspection-image-platform/blob/main/records/model-final-evaluation.md)를 따른다.

Label Studio와 재학습 관리의 후속 흐름도 구현·검증했다. 실제 query bridge 후속 GET 두 번은 단일 페이지 결과이며, 실제 다중 페이지/prepare/Label Studio 연속 실행 전체를 추가 검증한 것으로 확대하지 않는다. 이 기록 범위 정리는 [PR #16](https://github.com/junhang-dev/inspection-image-platform/pull/16)에 있으며 후보 자동 학습은 재개하지 않는다.
