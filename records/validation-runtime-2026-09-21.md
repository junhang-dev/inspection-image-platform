# 실제 브라우저·파일 저장 독립 검증

검증일: 2026-09-21. 기능 확인과 모델 성능, 자동 브라우저 검사와 실제 비개발자 사용자 검수를 구분한다. 아래에서 실제 확인한 범위만 완료로 표시하며 남은 항목을 전체 완료로 합산하지 않는다.

## 환경과 입력

- 로컬 Next/React 운영 화면과 MySQL/MinIO API. 시작 기준 커밋 `46f8cd23b6032741d08310b0108b205df5ae9787` 위의 구현 담당 미커밋 운영 build를 검사했다. 최종 커밋 검증으로 표시하지 않는다.
- Playwright CLI 0.1.21의 실제 headed 브라우저로 조작·스크린샷 저장. 제품 코드는 수정하지 않았다.
- 공개 demo 5개를 각각 두 번 사용한 검증용 업로드 10개, 총 13,139,268bytes. 같은 사진의 반복 업로드이며 학습 데이터 10개 추가나 test 10장 평가가 아니다. 제품 담당의 별도 demo 10개와 합쳐 전체 화면 20개로 보일 수 있다.
- 검증 전용 포인트·계획·수정 사유에 `validation` 표시. 실제 현장 검사·보수 판단으로 사용하지 않는다.

배포 담당은 이후 실제 외부 HTTPS 브라우저에서 demo5 선택·업로드·AI 판독 및 새 썸네일 5개 렌더링, 정확한 Origin의 OPTIONS204를 별도로 확인했다고 보고했다. 이는 배포 담당의 실행이며 검증 담당의 독립 외부 쓰기 검사로 표시하지 않는다. 전체 저장 사진은 해당 추가 검사 후 30개이며 승인 demo5의 반복 업로드다.

민감정보 없는 공개 demo 화면을 실제 캡처했으며, 사진 UUID·objectKey·pointId와 4종 해시·이력 JSON·다운로드 파일을 로컬 증거로 보존했다. 상세 경로와 검증 데이터 식별자는 Git 제외 `validation-browser-2026-09-21.local.md`에 있다. 로그 PASS만으로 판정하지 않았다.

## 시간 관찰의 한계

업로드 POST의 브라우저 resource timing은 1,394.4ms, 첫 사진 DB 생성부터 마지막 실제 추론 완료까지의 서버 이력 차이는 14.38초였다. 전자는 전체 사용자 입력·화면 반영 시간, 후자는 최종 UI 렌더 시간까지 포함한 측정이 아니다. 각 1회 관찰이며 계약의 사용자 시간 목표 전체를 합격으로 선언하지 않는다.

## 아직 남은 검증

- 사용자가 공개 가능한 사진의 일반 업로드를 추가 승인했고 제품 담당이 반영 중이다. 새 파일 선택 UI와 새 설정에서의 실제 업로드·저장 검증은 아직 하지 않았다. 앞선 demo 전용 결과는 당시 설정의 이력이다.
- API·DB·MinIO 재시작 후 데이터·바이트 독립 비교와 기존 UUID의 화면 재조회 캡처를 마쳤다. 재시작 후 추가한 보수 진행·완료와 해제·재지정 이력은 브라우저/API 재조회로 확인했으며, 이 추가 상태에 대한 두 번째 서비스 재시작 검사는 하지 않았다.
- 잘못된 파일·판독 실패와 복구, 처리 중 동시 사용자 조작 및 시간 목표 전체는 이 담당의 추가 검증이 필요하다. 제품 담당의 별도 검사와 혼동하지 않는다.
- 허브 보고로 동료가 외부 사이트에서 실제 리뷰 중이다. 이 담당이 자동 조작한 증거와 구분하며, 비개발자 팀원의 전체 시나리오 수행 및 막힘 수정 후 재확인 완료는 아직 확인하지 못했다.
- 모델 화면에 최종 test 60%로 사용자 목표 70% 미달이 표시된다. 실제 추론 기능이 동작해도 모델 성능 완료가 아니다. 평가 재실행이나 최종 test 기반 튜닝은 하지 않았다.
