## 목표·경계

- 목표: 개발 서버에서 메뉴 접기·펼치기와 계획 화면의 반응형 동작을 보완하고, 재촬영 후 새 계획으로 가는 길을 사용자가 다시 찾을 수 있게 한다.
- 경계: 등급 기준, 보수 조치 규칙, 모델, 로그인·권한 정책, 사진·이력 데이터는 바꾸지 않는다. 새 사진을 과거 재촬영 기록에 자동 연결하거나 재촬영 표시를 자동 해제하지 않는다.
- 완료 조건: 실제 개발 화면에서 주요 흐름을 읽기 전용으로 살펴보고, 코드·자동 검사·타입·운영 후보 빌드 결과를 기록한다. 운영 전환은 같은 웹 후보와 기존 데이터·API 보존 상태를 확인한 뒤 별도로 기록한다.

## 실제 변경

- 901px 이상 화면에 좌측 업무 메뉴 접기·펼치기 버튼을 추가했다. 접힌 상태에서 메뉴 아이콘을 유지하고 버튼에 접근성 이름과 상태를 제공한다.
- 검사계획의 `목록 옵션` 패널은 넓은 화면에서 버튼 왼쪽에 맞춰 펼친다. 1150px 이하에서는 패널을 목록 안에 배치해 사이드바 뒤로 숨거나 화면 밖으로 잘리지 않도록 했다.
- 저장된 재촬영 표시 사진의 상세 화면에 `재촬영 계획 만들기`를 계속 제공한다. 열리는 계획에는 같은 생산팀·랙을 미리 선택한다. 기존 사진과 판독 이력은 유지한다.

## 사용자 관점의 확인

- 개발 화면 1280×720에서 좌측 메뉴를 접고 다시 펼쳤다. 아이콘 메뉴와 넓은 메뉴가 각각 표시됐다.
- 검사계획에서 생산팀·랙, 상태, 검색, 목록 옵션이 보이고, 목록 옵션의 범위·정렬 선택을 확인했다. 1280px 화면에서는 옵션이 사이드바 아래에 가려지지 않았다.
- 홈의 3등급 수(개발 데이터 75장)를 눌러 사진 목록으로 이동했다. 사진 등급 필터가 3등급으로 설정됐다.
- 재촬영 표시가 저장된 개발 사진 `15 08 03.JPG`를 열었다. 상세의 `재촬영 계획 만들기`가 활성화됐고, 새 계획 화면에 정유2팀·파이프랙 2가 미리 선택됐다. 새 계획은 저장하지 않았다.
- 보수관리 행에서 사진별 보수 상세를 열었다. 진행 상태, 방법, TA 작업 포함 여부가 별도 입력임을 확인했다.
- 워크리스트 화면에서 조건에 맞는 묶음 0개와 미배정 TA 사진 2장을 확인했다. 업무 묶음을 만들거나 사진을 수정하지 않았다.
- 운영 후보의 로컬 미리보기에서는 기존 공유 API를 읽기 전용으로 조회했다. 운영 데이터는 300장/112건, 개발 데이터는 303장/108건으로 서로 다른 범위임을 확인했다. 이 값은 배포 전 데이터 보존 비교의 기준값으로 사용하지 않는다.

## 첫 사용자 피드백 수집 제안

- 대상: 관리자, 업무 담당자, 조회자에서 각 1명 이상, 총 3~5명.
- 방식: 개발 서버의 테스트 계정과 테스트 사진만 사용하고, 20분 내외의 무안내 과제를 진행한다. 진행자는 설명을 보태지 않고 망설임·잘못 누른 곳·되돌아간 지점을 기록한다.
- 과제: 검사계획 찾기 → 등급으로 사진 찾기 → AI 결과와 사람 판정 구분하기 → 재촬영 계획 창까지 이동하기 → 보수 기록과 TA 묶음의 차이를 말해보기 → 화면 폭을 바꾸고 메뉴 찾기.
- 기록 필드: 역할, 화면 폭, 과제, 첫 행동까지 걸린 시간, 막힌 위치, 되돌아감·오클릭, 완료 여부, 사용자가 한 말, 심각도, 같은 문제가 나온 횟수, 익명 캡처.
- 관찰된 사용 문제와 새 기능 요청을 분리한다. 한 사람의 선호를 업무 규칙으로 확정하지 않는다. 완료 실패·잘못된 데이터 입력 위험은 즉시 수정 후보로 올리고, 반복된 불편은 다음 스프린트에서 우선순위를 정한다.
