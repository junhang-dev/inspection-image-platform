## 입력과 실제 변경량

승인된 `image/demo/demo-01.jpg`의 바이트를 그대로 복제한 두 파일을 사용했다. 파일당 2,965,056bytes이며 SHA-256은 `0510d0827704d8ec297bdecdebfd2eb7f65c44521e662fa8532036e47a610838`이다. 이름은 QA 식별용이고 등급 정답으로 사용하지 않았다. 원본 300장·고정 test·기존 split은 사용하거나 변경하지 않았다.

격리 환경은 사진 13→15, 포인트 27→31, 계획 7→9가 됐다. 신규 검증 계획 두 개·포인트 네 개·사진 두 개, 검증 계획 연결/상태 PATCH 성공 여섯 번, 새 QA 사진 판단 PATCH 성공 한 번을 기록했다. 성공한 계획 PATCH 중 다섯 번은 UI 연결, 한 번은 실제 경쟁 저장 재현이다. 추가로 허용되지 않는 note 변경 요청은 422, 실제 구버전 연결 요청은 409로 거절됐다. 최종 사진 A는 AI4/사람3/version1, B는 AI4/사람 미지정이다. 실제 현장 업무나 보수 완료 증거가 아니다.

## 실패한 자동화 시도와 한계

초기 실행에서 select의 라벨 탐색, 달력·목록의 동일 이름 버튼 구분, 업로드 후 계획 상세로 돌아오는 모달 전환을 잘못 가정해 자동화가 중단됐다. 각 중단까지 실제 생성된 자료를 보존하고 이어서 사용했으며 성공하지 않은 단계를 PASS로 기록하지 않았다. 충돌을 만들려던 첫 요청은 API가 허용하지 않는 note 필드 때문에 422로 거절돼 충돌이 발생하지 않았다. 그 시도의 새 포인트는 정상 연결됐고 그대로 보존했다. 이후 허용된 상태 변경으로 실제 충돌을 만들어 위 결과를 확인했다. 원본 로그와 보정 스크립트를 모두 보존했다.

사진 선택은 `setInputFiles`를 사용했으므로 OS 네이티브 파일 선택창 확인은 아니다. 타이밍 목표·사람 조작 속도·v2 전체 흐름 시간은 측정하지 않았다. 사진 실패 후 계획 보존, 대용량/부분 업로드 실패, v2 재시작, 목적 분리, 보수 워크리스트, KPI 전체 집계, 지도·300장 배치는 이번 범위에 포함하지 않는다.

화면 증거에서 필터의 `1장`과 `미조회` 문구가 세로 줄바꿈되는 가독성 문제가 보였다. 상태 의미와 조작은 확인됐으므로 첫 관계 단위의 차단 결함으로 보지 않았고 후속 가독성 작업에 전달했다. 브랜드 이름 확인을 전체 가독성 PASS로 확대하지 않는다.

동결 모델의 기존 최종 test 60%/목표70% 미달은 유지한다. 이번 승인 입력의 모델 연결 성공은 새 모델 성능 검증이 아니다.

## 증거와 인계

실제 요청·응답, fixture ID와 전후 JSON, 후보 해시 대조, 중단·재개 로그, 원본 다운로드 해시, 화면 61~70을 Git 제외 로컬 증거로 보존했다. 화면 61~70은 직접 열어 확인했다. 상세 위치는 `records/validation-browser-2026-09-21.local.md`의 첫 단위 항목에 연결한다. 공개 문서에는 로컬 원본 경로·운영 데이터 목록·DB 내용·인증값을 포함하지 않는다.

V2-04는 이 후보의 실제 두 계획 분리 사례를 통과했다. V2-01은 이름, V2-03은 인계된 계획/포인트/업로드 및 충돌 경로, V2-13은 팀·랙 문맥만 확인했다. 그 외 조건과 후속 항목은 미실행이며 v2 전체 완료로 표시하지 않는다.
