## 실제 보수 흐름과 재시작 검증

실제 API·DB와 브라우저에서 상태·방법·워크리스트 저장, 같은 포인트의 계획별 분리, 두 창의 저장 충돌, 오류 후 입력 보존, 이력과 마지막 페이지 접근을 확인했다. 공유 반영에서는 기존 사진 65개·계획 4개를 그대로 보존하고 포인트 4개는 이관 표시·수정 버전·수정 시각만 바꿨다. 보수 기록 4개와 이력 8개를 추가했으며 기존 이력 236개·완료 업로드 세션 1개·파일 조각 1개는 유지했다. 이 전후 자료는 배포 담당이 독립 재계산했다.

별도 격리 환경에서 승인 샘플을 새로 업로드한 두 흐름을 수행했다. 실제 모델 결과를 유지한 재촬영 사유·라벨링 후보·작업 예정/도장/TA/워크리스트 저장과 사진·보수 이력을 확인했다. 웹·API·MySQL·MinIO의 정상 재시작 뒤 사진 2개·계획 2개·포인트 2개·보수 2개, 이력 17개, 업로드 세션 2개·파일 조각 2개가 동일했다. API 재조회와 MinIO의 두 원본 파일 크기·SHA-256도 확인했다. 새 브라우저의 localStorage 큐 복원은 이번 재시작 검증에 포함하지 않는다.

초기 두 흐름의 213.820초와 155.922초에는 자동화 선택자 오류·복구 개입이 포함돼 유효한 연속 시간으로 사용하지 않는다. 후속 사전 환경 실패 두 건은 제품 쓰기·측정 시작 전 중단했으며, 업로드 전 선택자 오류로 실패한 한 건은 같은 계획·포인트에서 기능만 복구했다. 이 실패들을 정상 실행 시간에 합치지 않았다.

수정 후 새 전용 세션에서 **중간 개입 없는 단일 연속 실행이 성공했다. 총 3,969.700ms에서 AI 결과만 기다린 1,297.500ms를 빼면 업무 조작은 2,672.200ms**다. 같은 문서의 단조 시계로 기록한 15개 이벤트, 새 계획·포인트·업로드 세션·사진·보수 기록과 이력을 연결했다. 허브도 원시 이벤트의 시간·ID·원래 AI 보존을 독립 재계산했다. 승인 사진 한 장의 입력·API·MinIO 원본 크기와 SHA-256, 화면, 기존 세 기록의 값·이력 보존을 QA가 확인했다. 이는 에이전트 자동 조작 1회가 60초 이내였다는 관찰이다. 사람의 판단 시간이나 OS 선택창에서 파일을 찾는 시간, 모든 환경의 성능을 보장하지 않는다. 추가된 두 사진에 재시작 검사를 반복하지 않았으므로 위 재시작 근거는 최초 두 사진에 한정한다.

## 10장 배치와 후보 해제

승인 사진 한 장의 동일 바이트 복제 10개를 새 경로에서 올렸다. 같은 브라우저 시계로 저장 확인까지 8,814.6ms, 저장 확인 후 전체 AI 결과 표시까지 6,236.9ms, 업로드 시작부터 전체 결과까지 15,051.5ms를 관찰했다. 저장 확인 시 이미 5장의 판독이 끝났으므로 두 번째 시간을 10장 순수 모델 계산 시간으로 표시하지 않는다. 10개 업로드 세션·사진·객체의 대응과 각각 2,965,056바이트 및 SHA-256을 대조했다. 이는 서로 다른 현장 사진이나 모든 환경의 성능 보장이 아니다.

배치 판독이 미완료인 동안 계획 생성·캘린더·대기 목록 조회가 가능했다. 계획 구간 168.4ms 중 실제 processing과 겹친 시간은 약 12.7ms이며 저장·캘린더 확인 때는 4장이 pending이었다. 따라서 계획 절차 전체가 실제 모델 처리 구간 안에서 완료됐다고 확대하지 않는다. 처리 중 숨긴 사진 한 장은 판독 완료 뒤에도 숨김과 사유·버전을 유지했고, 일반 목록·KPI·지도는 모두 9장이었다. 보이는 사진 9개의 API 파일 크기·해시가 일치했고 숨긴 사진은 404였다. 기존 네 사진 등의 보존은 QA가 24개 비교 성공을 기록했으며, 허브의 이 묶음 독립 검토에는 이전 raw가 없어 그 전체 보존을 다시 계산하지 않았다.

후속 사진 한 장에서 재촬영 표시를 해제해도 라벨 후보는 유지됐고, 라벨 후보까지 해제한 뒤 각 목록은 0장이었다. 허브의 독립 전후 비교에서 각 단계는 해당 표시와 수정 버전·시각만 바뀌었고 원래 AI·사진 관계·연결 보수·기존 이력 4개는 같았다. 새 이력은 정확히 2개였다. 화면 탐색 후 필터를 다시 맞춰 확인했으므로 최초부터 중단 없는 성공으로 기록하지 않는다.

현재 동결 모델과 같은 기존 결과 242개(train 사진 기록 232개와 test 10개)를 보존하고 결과가 없던 validation 58개만 판독했다. 기존 train 231/validation 58/test 10/제외 중복 1의 분리는 바뀌지 않았다. 독립 raw 비교에서 새 판독은 해당 58개의 AI 관련 값과 이력만 바꿨고 cached train·test 사진의 전체 행은 같았으며 새 test 판독 이력은 0개였다. 담당은 고정 test를 새로 추론하거나 튜닝하지 않았다고 보고했다. 이 raw 비교가 기록 밖 모델 호출의 부재까지 독립 계측한 것은 아니다.

299개 고유 객체의 합계는 483,481,091바이트다. 제품의 실제 객체·API 재조회 기록을 독립 대조해 299개 전체의 ID·저장 키·크기·SHA-256 대응을 확인했다. 등록 재실행과 웹·API·MySQL·MinIO 재시작 전후 8개 raw 테이블·374개 이력·299개 객체 증거 배열이 같았다. JSON 파일의 측정 시각과 비교 대상은 달라지므로 파일 바이트 전체가 같다는 의미는 아니다.

제품 기록의 공개·공유 로컬 host별 메타데이터·원본·썸네일 응답 6개가 404였고 익명 접근 403 한 건을 확인했다. 대상 ID와 전체 URL은 해당 기록에 없어 이 결과를 모든 사진의 모든 외부 경로 검사로 확대하지 않는다. 원본 300장과 이 환경의 DB·분리 목록·원본 화면은 Git이나 공유 사이트에 공개하지 않았다. 공유 제품 버전은 계속 유지한다.

## 남은 완료 판정

실제 로컬 화면에서 12랙·12포인트의 각 25장, 네 계획의 각 75장(50+25), 전체 목록 6페이지의 고유 사진 300개와 확대 100→200→100을 확인했다. 기존 train에서 확인한 사진 네 개의 상세와 계획·포인트 연결도 일치했다. 고정 test 픽셀을 열지 않도록 이 브라우저 검증에서는 train 사진만 렌더링했으므로 모든 사진의 화질 검증으로 확대하지 않는다.

검수 중 정유3팀의 긴 랙 마커가 겹쳐 중앙 클릭을 가로막는 문제를 발견했다. 선택한 팀 구역을 확대하고 44px 번호 마커로 바꾸면서 전체 이름은 접근성 이름·우측 목록에 유지했다. 저장된 좌표와 ID는 바꾸지 않았다. 수정한 실제 빌드와 소스 해시를 확인한 뒤 1440·390·320px 각 네 팀의 3랙, 총 36개 중앙 클릭을 강제 클릭 없이 통과했다. 마커 간 최소 간격은 12.095px였고 세 폭의 확대·복귀도 통과했다. 이 재검수 범위에 남은 P1/P2 문제는 없다.

별도 격리 환경에서 모델 연결 실패를 한 번 주입한 승인 사진의 API 재시도와 같은 ID 완료를 확인했다. 57바이트의 손상 입력도 API가 422로 거절하고 사진을 등록하지 않았다. 독립 UI를 위해 추가한 사진 한 장에서는 ‘AI 결과 없음’·실패 안내·재요청 버튼을 직접 확인했다. 버튼 한 번과 재요청 HTTP 200 한 건으로 같은 사진이 error→pending→done으로 바뀌고 실제 4등급 결과와 이력 6개가 표시됐다. 해당 단위의 주입 실패 1회 뒤 실제 동결 모델 호출은 1회였다. 제품의 전후 raw 감사에서 같은 사진·업로드 세션·저장 키·파일 조각·2,965,056바이트·SHA를 보존했고 기존 이력 3개에 3개만 추가됐다. 앞서 API로 완료한 사진과 이력·원본·증거도 그대로였다.

재요청 뒤 상세창이 닫혀 관찰 스크립트의 ‘창 유지’ 가정이 시간 초과됐지만, 재클릭 없이 목록과 같은 사진의 상세를 다시 열어 결과를 회수했다. 이 관찰 오류를 제품 판독 실패나 중간 개입 없는 시간 측정으로 사용하지 않는다. 손상 입력의 API 거절과 판독 실패의 실제 화면 복구는 구분해 기록한다.

네이티브 OS 선택창의 시각·취소 검증은 도구의 앱 접근 승인 대기로 미확인이다. 브라우저 file chooser 발생·선택 파일 반영과 네이티브 창의 직접 관찰을 구분하며, 이 승인 대기가 다른 구현·검증을 막지는 않는다. 이미 확인한 보수 동시 저장·대용량 원본 보존·정상 재시작은 이유 없이 반복하지 않는다.

모델 성능은 **train 99.57%로 90% 기준 PASS, 고정 test 60%로 70% 기준 FAIL**이다. 이번 UI·조회·지도 개선으로 이 판정이 바뀌지 않는다. 원본 300장의 기존 분리·모델 가중치·비밀을 Git이나 공유 서비스로 추가 전송하지 않았으며, 전체 요구 완료를 선언하지 않는다.
