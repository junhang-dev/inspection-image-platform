# 원본 300장의 전용 로컬 연결

2026-09-22 제품 작업. 작업 브랜치는 `codex/jun/platform-private-import`이고 부모 커밋은 지도 수정 `776bcf95a4f1126163b7b3036ef2eaf0e3438f1b`다. API 구현·실행의 시작 기준은 보수 버전 `6fbae158e657572ec952924b3c68722fad08bb9e`다. 기존 사진 전체를 가상 팀에 균등 배치하고 조회하라는 승인 범위에서 같은 Mac의 격리된 로컬 제품을 구현했다. 원본 300장의 공개 배포는 포함하지 않는다.

## 구현

별도 Compose의 MySQL·MinIO, schema/bucket에 한정된 새 사용자, 소유자 전용 자격·임시 폴더를 구성했다. API4100과 웹3100은 loopback에만 연결한다. 실행 범위와 메타데이터 계약, DB·bucket 표식을 초기화 전에 확인하며 잘못된 공유 설정으로 대신 시작하지 않는다. 실제 설치된 MinIO IAM 정책·사용자 연결과 MySQL의 literal schema grant를 확인했다.

manifest+sourceId registry에 사진·계획·포인트 UUID와 객체 키를 먼저 예약한다. 원본 전체 크기/SHA를 확인하고 바이트 그대로 저장한다. 사진·등록 이력·registry 완료는 같은 transaction으로 확정한다. 동일 DB 잠금 연결을 잃으면 복사·모델 요청을 취소하며 재실행은 완료된 사진과 사람 판단·이력을 보존한다.

sourceId 또는 실제 SHA로 고정 평가 사진을 식별한다. 가져온 사진은 모두 자동 큐·재시도 대상에서 제외한다. multipart/청크 완료/worker/재시작 복구/모델 전송 전에도 같은 정책을 적용한다. 동결 보고서의 모델·전처리·checkpoint·manifest·원본 연결을 검증하며, 판독 시각이 없는 캐시는 시각 미확인으로 표시한다. 필요한 비평가 원본만 명시적으로 동결 모델에 보낸다.

## 실제 모델 연결 실패와 복구

제품 저장소와 다른 전용 MySQL·MinIO·API·web·프록시를 구성하고 승인된 demo 복제본으로 확인했다. 첫 모델 요청을 프록시에서 끊어 실제 연결 실패를 만들고 다음 요청만 실행 중인 동결 모델로 전달했다. 첫 API 검사에서 error·AI 없음 → 재시도 → done을 확인했으며 시도2회·실패주입1회·실제 모델 호출1회였다. 동일 사진 ID·업로드 세션·객체 키·전체 원본 바이트와 기존 이력4개를 보존하고 이력3개만 추가했다. 미리 기록한 사람 등급·라벨링 후보·수정 버전도 유지됐다.

실제 응답은 4등급이며 모델·전처리·checkpoint는 기존 동결 버전과 일치했다. 손상된 합성 PNG 57바이트는 한국어 안내와 HTTP422로 거절했고 새 사진은0개였다. 이 검사에서 원본300 읽기·등록·평가 사진 호출은0회다.

추가 demo 한 장으로 독립 브라우저에서 실패 안내·AI 결과 없음·기존 이력3개를 확인한 다음 **판독 다시 요청 버튼을 한 번** 눌렀다. 네트워크 기록의 retry POST도1개였으며 동일 사진이 error→pending→done으로 바뀌고 실제4등급·99.6%·동결 모델과 이력6개를 표시했다. 상세창이 자동으로 닫혀 관찰용 locator가 한 번 timeout됐지만 버튼을 다시 누르지 않고 목록에서 같은 사진을 열어 완료 화면을 확인했다. 읽기 전용 후속 감사로 시도2회·주입실패1회·실제 모델 호출1회, 원본 전체 바이트·사진/세션/객체 키·청크·기존3이력 보존을 확인했다. 첫 검사 사진·7이력과 최초 증거13파일도 불변이었다. UI 검수 브라우저를 닫고 슬롯을 반환했다. API 검사와 실제 버튼 조작 증거는 서로 구분해 로컬에 보존했다.

검수 후 전용 web·API·프록시와 MySQL·MinIO만 정상 종료했다. 전용 볼륨2개와 증거25파일 SHA는 보존했고 공유·원본 로컬 웹/API 및 동결 모델 health는 정상이었다. 두 구간을 합쳐 승인 demo의 실제 모델 호출은2회다.

## 원본 화면의 독립 검수

12개 랙·사진 묶음마다25개, 계획4개마다75개(50+25), 전체6페이지의 고유 사진300개를 확인했다. 팀별 학습 분리 사진 한 장씩 총4개를 열어 계획·포인트 연결을 확인했다. 고정 평가 사진의 픽셀을 새로 검수하거나 모델로 다시 보내지 않았다.

첫 지도 검사에서 발견한 랙 버튼 겹침은 독립된 [지도 수정](platform-map-marker-fix.md)으로 해결했다. 최종 BUILD_ID와 두 지도 파일 SHA를 대조한 뒤 PC·390·320px에서 총36회 중앙 클릭과 확대·축소를 통과했다. 잔여 P1/P2는0이며 검수 브라우저를 종료했다. 지도상 팀·랙·포인트는 시연용 가상 배치이며 실제 설비 위치의 증거가 아니다.

## 남은 구분

공유 API는 검증된 보수 버전 `6fbae15`를 유지한다. 지도 웹 수정은 독립 커밋 `776bcf9`로 분리했고 이 로컬 API·원본 저장소를 공유 환경에 전환하지 않았다. 새로운 공유 API 버전으로 전환하려면 명시적 메타데이터 계약·저장소 표식과 전환 검증이 필요하다. 로컬 원본300을 공개 URL에서 보여주려면 별도의 공개 범위 판단이 필요하다. 기능 동작과 자동화 수행 시간은 동료의 실제 사용 시간·현장 효과를 입증하지 않는다.
