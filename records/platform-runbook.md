# 로컬 플랫폼 실행과 범위

## 첫 실행

```sh
npm ci --cache .cache/npm
npm run setup
npm run infra:up
npm run build
```

저장소 준비 후 터미널 두 개에서 실행한다.

```sh
npm run start:api
```

```sh
npm start
```

- 화면: `http://127.0.0.1:3000`
- API: `http://127.0.0.1:4000/api/health`
- 모델: 별도 담당이 실행한 `http://127.0.0.1:8001/health`
- MySQL·MinIO는 Docker 영구 볼륨을 쓴다. 중지 시 `npm run infra:stop`; **볼륨 제거 옵션을 사용하지 않는다.**
- 비밀은 `npm run setup`이 무작위 생성한 Git 제외 `.env`에만 저장한다.
- `npm test`는 실행 중인 API의 오류 처리/출처 제한/AI 결과 주입 금지와 클라이언트 오류 안내·예시 맵 위치 규칙을 확인한다. 별도 API를 검증할 때는 `TEST_API_URL=http://127.0.0.1:3400/api`를 지정할 수 있다.
- `npm run smoke`는 공개 demo5장을 두 번 사용하는 10장 업로드·원본 바이트 재조회·실제 추론 검사다. 결과는 Git 제외 `records/platform-smoke.local.json`에 기록한다. 학습 표본으로 추가하지 않는다.

## 화면 업무

1. 사진 업로드에서 최대 10장 선택 → 기존 포인트 또는 새 설비·랙·포인트 연결. 위치를 모르면 미확인으로 저장한다.
2. 실제 AI는 별도 큐에서 판독한다. 준비되지 않은 모델은 판독 대기, 실행 오류는 실패로 표시한다.
3. 사진 상세에서 원래 AI 등급을 확인하고 필요할 때 사람 등급을 별도 기록한다. 재촬영 사유·라벨링 후보·수정자·변경 사유를 저장한다.
4. 포인트 관리에서 보수 검토/진행/완료·관리 대상·TA 포함을 기록한다. 수정 이력은 이전 값·새 값·시각·수정자·사유를 보존한다.
5. 검사 계획을 날짜와 포인트에 연결하고 캘린더에서 확인한다. 계획 이행 완료와 변경 이력을 조회한다.

## 배포 준비와 제한

- 로컬 Next 서버는 `/api/*`를 같은 Mac의 API로 전달한다. 브라우저는 상대 URL을 사용한다.
- 외부 프론트만 따로 배포할 때는 `NEXT_PUBLIC_API_BASE_URL`을 접속 가능한 Mac API의 승인된 URL로 빌드해야 한다. Vercel Functions를 통한 원본 업로드는 사용하지 않는다.
- `CORS_ORIGINS`에는 정확히 승인된 화면 주소만 추가한다. 현재 인증 기능은 없으며, 공개 가능한 사진만 사용자가 직접 선택하는 일반 업로드를 추가 승인받았다. 링크를 가진 사람은 사진과 업무 기록을 조회·수정할 수 있다.
- 전체 Compose 앱 구성은 `npm run stack:up`으로 실행한다. 웹·API 이미지 빌드와 별도 검증 프로젝트의 웹·API·MySQL·MinIO 4개 컨테이너 기동을 확인했다. **AI 모델은 Mac의 별도 프로세스**이며, 컨테이너 API가 `host.docker.internal:8001`로 연결한다. 모델까지 Compose로 통일됐다는 의미는 아니다.
- 예시 3D는 설비/랙 입력을 표시하는 개념 모형이며 실제 설비 좌표가 아니다.
- 모델 정확도 합격 여부·기능 동작·비개발자 사용자 검수는 서로 다른 완료 항목이다.
- 현재 조회는 유형별 최신 1,000개까지인 초기 프로토타입이다. 대량 운영을 위한 페이지네이션·계정 인증·다중 API 워커는 이번 기반에서 제공하지 않는다.

## 공개 demo 전용 모드

- `.env`의 `PUBLIC_DEMO_ONLY=1`은 서버에 승인된 demo5의 SHA-256만 허용한다. 혼합 묶음은 저장 전에 전체 거절한다. 기존 DB에 비승인 사진이 있으면 공개 모드 시작을 중단한다.
- `NEXT_PUBLIC_DEMO_ONLY=1`로 빌드하면 파일 입력을 숨기고 제공된 시연 사진 5장만 선택할 수 있다. 서버는 선택된 시연 파일의 SHA-256과 실제 디코딩을 검사한다.
- 이 두 값이 0이면 일반 사진 업로드가 가능하다. 운영 모드를 바꿀 때 API 재시작·화면 재빌드가 필요하다.
- 공개 demo 선택과 일반 로컬 업로드는 같은 저장·판독 코드를 사용한다. 파일명으로 허용 여부나 예측 등급을 정하지 않는다.
- 수정자는 현재 자가 입력이며 계정 인증으로 검증한 신원이 아니다.

## 승인된 공개 일반 업로드와 시연 사진 재사용

- 2026-09-21 추가 승인: 공개 가능한 사진에 한해 일반 파일 선택을 허용한다. 원본 300장·분리 목록·모델 가중치를 자동으로 올리거나 학습 데이터에 편입하지 않는다.
- 운영값은 `PUBLIC_DEMO_ONLY=0`, `NEXT_PUBLIC_DEMO_ONLY=0`, `PUBLIC_UPLOADS_ALLOWED=1`, `NEXT_PUBLIC_PUBLIC_UPLOADS_ALLOWED=1`이다.
- `PUBLIC_UPLOADS_ALLOWED`는 health 응답의 공개 업로드 안내 표시이고, `NEXT_PUBLIC_PUBLIC_UPLOADS_ALLOWED`는 화면 빌드의 공개 안내 표시다. **두 값은 접근 통제 스위치가 아니다.** 일반 사진을 서버에서 거절하려면 `PUBLIC_DEMO_ONLY=1`을 사용한다.
- 화면은 공개 가능한 사진만 선택하고 링크 보유자가 조회할 수 있음을 알린다. JPG/PNG 실제 디코딩, 최대 10장·장당 20MB·4천만 픽셀 제한을 적용하며 파일명 대신 UUID 저장 키를 쓴다.
- ‘시연 사진 5장 선택’ → ‘시연 사진 열기’는 `/api/demo-inspections`에 포인트 ID만 전송한다. 서버에 있는 승인 시연 파일을 SHA-256·실제 디코딩으로 확인하므로 사진 전체를 브라우저로 내려받고 재전송하지 않는다. 같은 포인트와 SHA-256의 사진이 이미 있으면 기존 ID·결과·사람 수정값을 재사용한다. 여러 번 눌러도 사진을 새로 만들지 않으며, 기존 중복 기록은 삭제하지 않는다. 기존 multipart의 `demo=1` 경로도 같은 제한을 유지한다.
- 일반 파일 선택은 같은 사진 바이트여도 별도 검사 기록을 생성한다. 시연 버튼의 중복 방지와 구분한다.
- 현재 외부 주소는 [검사 이미지 플랫폼](https://downtown-considered-permits-lancaster.trycloudflare.com)이다. 임시 터널이므로 Mac·제품 서버·모델·터널·네트워크를 유지해야 한다. 터널을 다시 만들면 주소가 바뀔 수 있다.

## 조회·지연·예시 맵

- 목록과 포인트 카드에는 최대 320×200 WebP 미리보기를 쓴다. 원본은 수정하지 않으며 상세 화면과 AI 판독은 원본을 사용한다. 변환 결과는 API 메모리에 최대 128개 보관한다.
- API 조회는 기본 10초, 시연 사진 요청은 30초, 일반 파일 전송은 180초 제한이 있다. 준비·전송·저장 후 목록 확인을 구분한다. 네트워크 단절·게이트웨이 HTML 오류·응답 손실은 실패로 알리고, 쓰기 요청은 목록에서 반영 여부를 먼저 확인하도록 안내한다.
- 예시 맵은 설비 식별자를 3개 모형 구역에, 랙을 5개 모형 슬롯에 결정적으로 배치한다. 실제 설비 도면이나 측정 좌표와 무관하며, 같은 슬롯에 서로 다른 입력이 대응할 수 있다. 설비 또는 랙 입력이 없으면 위치를 만들지 않는다.
- 포인트 추가나 목록 순서 변경으로 기존 좌표가 움직이지 않는다. 기본 표시 수는 12개이며, 선택한 포인트는 순서와 무관하게 단독 표시한다. 마커와 ‘선택 포인트 보기’는 해당 ID의 상세·연결 사진을 연다.
- 재시작 검증은 `scripts/verify-persistence.mjs --capture`로 전체 메타데이터·이력·원본 해시를 저장한 뒤, 재시작 후 같은 스크립트로 비교한다. `TEST_API_URL`과 `PERSISTENCE_REPORT`로 별도 검증 환경과 Git 제외 기록 파일을 지정한다. 원본 볼륨은 제거하지 않는다.
