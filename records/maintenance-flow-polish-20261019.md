# 2026-10-19 후속 조치 화면 정리와 운영 데이터 1차 정합성

## 사용자 승인 범위

후속 조치 아래의 출처·차이 문구를 제거하고, 상세는 조치를 먼저 고른 뒤 진행 상태를 선택하게 한다. 현재 운영 데이터는 직접 정리해도 된다는 사용자 승인에 따라 백업·이력을 보존하며 등급 기준 조치로 1차 정리한다.

## 변경과 검증

- 보수 목록에서 `담당자 지정`, `등급 자동 분류`, `등급 기준과 다름` 문구를 제거했다. 워크리스트의 TA 묶음 안에도 후속 조치를 표시한다.
- 사진 상세는 후속 조치 → 진행 상태 선택 상자 → 사유 순서다. 검토 필요·작업 예정·작업 중·완료의 단계 버튼을 제거했다. 조치를 바꾸면 초기 상태는 작업 예정으로 연결하고, 작업 중·완료는 유지한다. 조치 없음은 초기 상태에서 등록 전, 미정은 검토 필요로 연결한다. 이미 입력된 조치를 변경하지 않고 열기만 한 경우에는 저장 상태가 바뀌지 않는다.
- 사유 입력과 변경 이력, 충돌 방지, 기존 업무 상태 보존은 유지했다.
- 전체 검사 203개 중 192개 통과·0개 실패·선택 인프라 검사 11개 건너뜀. 조치 선택에 따른 초기 상태 연결 및 작업 중·완료 보존 검사를 추가했다.
- 개발 브라우저에서 조치 선택만으로 작업 예정이 연결되는지 확인하고, 실제 저장 후 DB의 조치·상태·입력 사유 및 이력을 대조했다. 해당 합성 자료는 검증 후 정리했다. 개발 인증은 해당 검증 실행에서만 비활성화했으며 운영 인증은 변경하지 않는다.

## 운영 데이터 정리 결과

- `scripts/reconcile-maintenance-methods.mjs`는 기본적으로 읽기 전용 예행 검사다. 적용은 명시적인 `--apply`에서만 수행하며 `local/` 아래 복구 백업 파일을 독점 생성한 뒤 하나의 트랜잭션으로 저장한다. 운영 시작 시 자동 실행하지 않는다.
- 현재 등급과 다른 조치 **45건**을 기존 사진별 ID에서 정리했다. 새 보수 기록이나 사진별 대체 기록은 만들지 않았다. 현재 등급은 사람 수정값을 우선했다.
- 기존 작업 상태·TA·목록 포함·표시·완료 후 새 근거 표시는 보존했다. 완료 기록의 수정 시각 변경이 근거 확인으로 오인되지 않게 기존 확인 상태를 명시적으로 보존했다.
- 기존 엔터티 416개 중 수정 대상 45개 외 **371개 내용은 동일**했다. 사진 300장·계획·원본 연결·TA 묶음 연결은 그대로다. 기존 이력 559개는 전부 보존하고 정리 이력 45개를 추가했다.
- 실제 API 전체 사진별 300건 조회에서 등급 기준 조치 불일치가 **0건**이다. 재예행 검사도 추가 변경 0건이었다.
- 기본 보수 대상은 111건이며 추적관리 69, 도장교체 18, 배관교체 24다. 수동 제외·재촬영 등 기존 목록 포함 규칙은 유지된다.
- 독립 읽기 전용 기술 검토 후 적용했다. 검토 중 발견한 완료 기록의 새 근거 보존 문제는 적용 전에 수정하고 예행 검사에서 검증했다.
