## 구현과 검토

서버의 동일 SQL 범위와 반복 읽기 트랜잭션으로 전체 COUNT·집계·포인트별 수·페이지를 반환한다. AI 큐는 공개 조회 범위와 별도이며 숨김을 되돌리지 않는다. 숨김의 직접 이미지/썸네일은 404이며 새 응답은 no-store다. 공개된 승인 지도 PNG 두 개와 인계받은 독립 지도 컴포넌트를 같은 계획·팀·랙·사진 집계에 연결했다.

화면의 이전 배열 API 소비를 페이지 조회로 바꿨다. 독립 검토에서 발견한 상세 사진 상태 고착, 첫 조회를 지도 0개로 표시하던 문제, 판단 폼과 숨김 폼의 동시 저장 경합을 수정했다. 선택 ID의 독립 조회, 조회 대기 표시, 모달 전체 작업 잠금으로 보강했다. 서버·UI 정적 재검토에 열린 P1/P2는 없었다. 이는 실제 브라우저 검증을 대신하지 않는다.

기존 smoke 도구는 업로드 ID를 개별 조회하고 정확한 UUID 집합을 확인한다. 빈 배열의 `every()`가 성공으로 통과하던 위험을 제거했다. 재시작/거절 검사 도구는 숨김·모든 목적·모든 사진 페이지를 확인하며 원본 검사 제외를 별도로 표시한다.

## 목적 확장 후속 후보

독립 QA는 초기 후보에서 네 카드의 Enter 이동과 정확한 사진 집합, 1,001개 마지막 페이지, 계획/포인트 상세 전체 건수, UI 숨김·복원·목적 변경, 지도 새 포인트 등록·계획 연결과 320/390px 가로 넘침을 확인했다. 최초 SSR 이미지 실패가 hydration 전에 발생하면 오류 안내가 누락되는 문제를 발견해 이미지 완료/실패 상태를 초기 effect에서도 확인하도록 수정했다. 수정 후 브라우저 결과는 별도로 기록한다.

R14의 명시적 목적을 계획·포인트까지 확장했다. 기존 사진에 목적을 전파하지 않으며, 실제 업무 사진이 있는 포인트는 그 조회 범위에서 유지한다. 사진이 없는 검증·발표용 포인트도 해당 목적 및 모든 목적 범위에서 조회한다. 신규 업로드는 선택 목적을 파일별 큐/서버 세션에 고정하고 같은 UUID의 다른 목적은 거절한다.
