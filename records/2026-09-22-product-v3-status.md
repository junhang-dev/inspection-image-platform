## 초기 계약 회수

제품 담당은 기존 코드에서 계획 업로드의 포인트 필수 검사, 포인트 JOIN 기반 팀/랙 조회, 12랙 카탈로그와 수동 보수 등록을 확인했다. 제품 후보 브랜치는 `e263593` 기준 `codex/jun/platform-product-v3`로 분리했고 운영 코드는 바꾸지 않았다.

허브·제품·독립 API 검토는 포인트 없는 새 보수 대상을 사진 ID별 한 항목으로 정했다. 랙은 목록의 묶음 기준이며 서로 다른 대상의 완료·방법을 자동 합치지 않는다. 기존 계획+포인트 보수는 ID·상태·이력을 유지한다. 유효 1~2등급으로 바뀌면 자동 대상에서 제외하되 기록은 보존하고 다시 3~5가 되면 같은 항목을 사용한다.

계획은 한 팀·중복 없는 랙 1개 이상·포인트 선택사항이다. 완료/취소/숨김 계획의 새 접수와 진행 중 전송 확정은 거절하되 기존 세션·임시 파일을 보존하고, 재개/복원 뒤 같은 세션으로 완료한다. 이미 완료된 업로드의 재조회·중복 complete는 닫힌 계획이어도 같은 사진을 반환한다. 기존 사진을 사용하는 팀/랙 제거는 409로 거절해 관계를 보존한다.

QA는 새 요구의 22개 회귀 행렬과 준비 기록을 `724cf36`/[초안 PR #21](https://github.com/junhang-dev/inspection-image-platform/pull/21)에 게시했다. 새 후보 실행은 아직 하지 않았다. 모델 담당은 ROI·실제 SHAP·제한 후보 실험 설계를 작성했다. 모델 예약 갱신은 이전 금지와 충돌한다는 자동 승인 검토 거절이 있었으나, 이후 해당 작업에서 사용자의 직접 승인 응답을 받아 기존 30분 모델 예약을 갱신하고 구현을 재개했다. 모델 브랜치는 `acaca0d` 기반 `codex/jun/model-roi-shap`다. 최초 후보 범위는 총 2개·각 최대 4epoch·CPU 2개·동시 1개이며 기존 고정 test와 운영 모델은 보존한다. 승인·착수를 실제 ROI/SHAP 실행이나 모델 개선 성공으로 표시하지 않는다.

배포 준비는 `e263593` 기반 `codex/jun/deployment-v3-fixed-url`의 격리 작업 폴더에서 진행한다. 기존 임시 경로는 유지했고, 고정 주소의 계정·도메인을 확인하기 위한 로그인 연결이 필요하다. 허브가 사용자에게 로그인과 도메인 보유 여부를 요청했으며, 담당은 그동안 고정 경로 구성·전환·복구·재기동 검증 계획을 준비한다. 고정 주소가 이미 확보됐다고 표시하지 않는다.

## 현재 운영 기준과 한계

공유 버전은 웹 `776bcf9`/PR19, API `6fbae15`/PR18, 모델 입력 `90dc402`/PR13이다. 기존 제출 경로는 [현재 임시 사이트](https://yellow-asp-says-needle.trycloudflare.com)이며 **고정 주소 요구는 아직 미완료**다. 원본 전용 로컬 구현은 `e263593`/PR20이다. 이번 차수에서 운영을 전환하거나 원본을 공개하지 않았다.

현재 서비스 모델의 train99.57% PASS/test60% FAIL은 이전 평가 결과다. 이번 추가 개발은 명시 요청된 로컬 후보 실험/ROI/설명 범위에서 진행하며, 이미 평가한 test10 재사용·원본 공개·새 사진 자동 학습·검증 전 운영 모델 교체는 포함하지 않는다. 새 후보의 정확도 향상이나 설명 품질은 아직 검증되지 않았다.

정책의 미확정 세부사항은 제품·모델의 실제 계약 회신으로 좁힌다. 비용·계정 권한·새 외부 전송이 필요한 고정 주소 경로는 실제 준비 상태를 확인한 뒤 최소 사용자 행동만 요청하고, 그 대기와 독립적인 제품/모델 작업은 계속한다.
