# 작업 결정과 독립 검토

반복 작업 중 사용자에게 매번 구현 방식을 묻기보다, 합의한 목표·범위·완료 조건 안에서 근거를 확인하고 독립 검토를 거쳐 진행합니다. 실제 무인 루프와 예약을 가동한 상태는 아닙니다.

## 한 결정의 순서

1. 실행 담당이 사용자 결정, 관련 파일, 현재 상태를 먼저 읽고 필요한 결정을 한 문장으로 적습니다.
2. 현실적인 선택지와 추천안, 변경할 파일, 되돌릴 방법, 확인할 결과를 준비합니다.
3. 작성자와 다른 검토 담당이 같은 근거를 보고 범위·실패 가능성·검증 누락을 확인합니다. 회사 자료를 새 외부 서비스로 보내 검토시키지 않습니다.
4. 검토 결과를 `진행 가능 / 수정 후 재검토 / 사용자 판단 필요`로 남깁니다. 이미 허용된 범위이고 도구 권한도 충족하면 실행 담당이 진행합니다.
5. 실제 변경과 검사 결과를 확인하고 의미 있는 단위로 커밋합니다. 실행하지 않은 검사를 통과로 기록하지 않습니다.
6. 아침에 볼 결정 문서에 근거·검토·결과·남은 문제를 남깁니다.

## 자율 진행과 사용자 판단의 경계

합의한 파일 범위 안의 구현·수정·테스트·문서화·로컬 커밋은 기존 승인에 따라 진행합니다. 원격 대상·공개 범위·허용 파일이 이미 확정된 push도 합의한 조건과 실제 검증을 따릅니다. 같은 허가를 반복해서 묻지 않습니다.

목표·데이터 사용 범위의 변경, 새 외부 전송 대상, 추가 비용, 계정·권한 확대, 보존되지 않은 데이터 삭제는 독립 검토자의 추천만으로 승인하지 않습니다. 검토가 해결하지 못한 중요 판단은 해당 작업을 보류하고 다른 독립 작업을 이어갑니다.

독립 기술 검토와 Codex/운영체제의 실행 승인은 서로 다릅니다. 검토자가 허용했다고 플랫폼의 승인 요청이 사라지지는 않습니다. 권한이 거절되면 같은 차단을 다른 도구로 우회하지 않고 원인과 필요한 결정을 남깁니다.

## 다음 날 확인할 결정 기록

상세 결정 문서는 로컬 전용으로 보관합니다. 공개할 요약은 내부 경로·사진·원본 파일명·인증 정보가 없는지 따로 확인합니다.

| 항목 | 기록할 내용 |
|---|---|
| 시간·작업 | 언제 어떤 결정을 했는지 |
| 질문·선택지 | 불확실한 점, 고려한 대안 |
| 결정·근거 | 선택과 기존 사용자 승인/자료 |
| 독립 검토 | 검토 담당, 지적, 반영 결과 |
| 변경 | 파일·커밋·원격 반영 여부 |
| 검증 | 실제 실행한 검사와 결과 |
| 승인 이력 | 요청 이유, 적용 범위, 승인/거절/대기 상태 |
| 남은 일 | 미검증, 위험, 사용자 판단 필요 여부 |

아침 요약은 `완료 / 진행 중·보류 / 사용자가 정할 것`으로 정리하고, 자세한 기록으로 연결합니다. 예약 주기와 무인 실행 권한은 별도 준비와 리허설 후 결정합니다.
