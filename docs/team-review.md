# 동료 검수: 사진 업로드부터 후속 이력까지

이 문서는 비개발자 팀원이 실제 화면으로 전체 흐름을 확인할 때 사용할 **선택 피드백 진행표**다. 2026-09-21 후속 합의에 따라 이 표가 비어 있거나 GitHub에 사람 검수 결과가 없어도 에이전트의 구현·검증·개선은 계속한다. 빈칸과 체크되지 않은 항목은 사람 검수 미실시를 뜻하며, 에이전트가 대신 체크하지 않는다. 에이전트의 실제 브라우저·백엔드 검증과 동료의 실제 사용 결과를 구분한다.

공유 주소와 실행 상태는 [운영 안내](https://github.com/junhang-dev/inspection-image-platform/blob/main/records/platform-runbook.md) 또는 담당자의 최신 안내를 확인한다. 새 배포 후에는 화면을 새로고침한다. 공개 가능한 사진만 직접 선택하며, 링크를 가진 사람이 사진과 업무 기록을 조회·수정할 수 있음을 알고 진행한다. 회사 원본·학습 목록·가중치를 검수 자료로 올리지 않는다.

## 검수 준비

- 검수 일시 / 담당 역할: ____________________
- 화면 버전 또는 담당자가 전달한 빌드: ____________________
- 사용할 공개 가능 사진: ______장 / 합계 ______MB
- 검수용 설비번호·랙·포인트 이름: ____________________

포인트와 계획 이름, 변경 사유에는 `검수용`을 붙인다. 검수용 사진의 보수 상태를 바꾸는 것은 기능 확인이며 실제 현장 보수 완료 기록이 아니다. 시연 버튼은 기존 사진을 재사용하므로 **새 파일 업로드 검증은 일반 파일 선택으로 수행한다.**

## 실제 업무 진행표

| 순서 | 화면에서 할 일 | 확인할 결과 | 결과 / 막힌 점 |
|---:|---|---|---|
| 1 | 사진 업로드에서 일반 사진을 선택하고 설비번호·랙·새 포인트를 입력해 저장 | 선택한 파일 수와 새 사진 수, 입력한 설비·랙·포인트가 일치한다. 위치를 입력하지 않은 사진은 미확인이다. | |
| 2 | AI 판독 중 검사 계획이나 포인트 화면으로 이동 | 다른 업무를 계속할 수 있고, 판독 완료 후 숫자 등급과 보수 필요/불필요 분류가 나온다. | |
| 3 | 해당 포인트를 dummy 3D 맵에서 선택하고 상세·사진을 확인 | 설비·랙 안내가 입력값과 같고 같은 포인트의 사진으로 이어진다. 예시 위치와 실제 설비 좌표를 구분할 수 있다. | |
| 4 | 사진 상세에서 사람 수정 등급과 사유를 저장한 뒤 다시 조회 | 원래 AI 결과가 남고 사람 수정값이 별도로 보인다. 수정자·시각·사유·전후값을 확인할 수 있다. | |
| 5 | 재촬영 사유와 라벨링 후보를 지정한 뒤 목록을 확인하고 해제 | 지정한 사진이 해당 목록에 나타나고 해제하면 빠진다. 변경 이력은 남는다. | |
| 6 | 포인트를 관리·TA 대상으로 지정하고 보수 검토→진행→완료를 사유와 함께 기록 | 단계별 상태와 이력이 보이고, 관리·TA 포함을 해제하거나 다시 지정할 수 있다. | |
| 7 | 같은 포인트의 다음 검사 계획을 만들고 캘린더에서 열기 | 날짜·포인트가 일치하고 계획에서 해당 포인트와 TA 워크리스트로 업무를 이어갈 수 있다. | |
| 8 | 화면 새로고침 후 사진·수정값·후속 상태·계획·변경 이력을 다시 열기 | 저장한 내용이 그대로이며 실제 사진이 정상 표시된다. | |

실패한 항목은 화면 문구, 클릭한 순서, 기대한 결과를 적는다. 수정이 배포된 뒤 같은 순서로 다시 확인하고 아래에 결과를 남긴다.

## 시간 기록

브라우저에서 실제로 기다린 시간과 사람이 입력한 시간을 함께 기록한다. API 응답 시간만으로 이 표를 채우지 않는다. 한 번의 측정은 그 환경의 관찰값이며 모든 환경의 성능을 보장하지 않는다.

| 기준 | 시작 → 종료 | 실제 시간 | 판정 |
|---|---|---|---|
| 계획 30초 이내 | 계획 만들기 시작 → 저장된 계획이 캘린더에 표시 | | |
| 10장 업로드 30초 이내 | 파일 10개 선택을 마치고 업로드 동작 → 10개 모두 저장·접수 결과 확인 | | |
| 10장 판독 3분 이내 | 10개 업로드 접수 완료 → 10개 모두 실제 AI 결과 표시 | | |
| 조회 수초 | 대시보드/사진/이력 열기 → 필요한 내용 표시 | | |
| 전체 업무 조작 약 1분 | 대표 업무 시작 → 저장 결과·이력 재조회, AI 결과만 기다린 시간은 별도 | | AI 판독 대기 제외로 사용자 확정 |

위 계획·업로드·추론 구간은 [검증 계약](https://github.com/junhang-dev/inspection-image-platform/blob/codex/jun/validation-contract/docs/validation-contract.md)의 P01~P03과 같다. 대표 전체 업무 조작은 별도로 측정한다. 추가로 파일 선택·포인트 입력은 ______초, 사진 선택 시작부터 저장 완료까지는 ______초, 업로드 시작부터 모든 AI 결과 표시까지는 ______초라고 기록한다. AI 결과만 기다린 시간은 ______초이며, 판독 중 다른 업무를 수행한 시간은 조작 시간에 포함해 이중 차감하지 않는다. 업로드·추론 하위 구간이 통과해도 전체 사용 흐름의 1분 기준까지 통과했다고 표시하지 않는다. 최초 화면 로딩, 느린 네트워크, 다른 작업의 동시 실행처럼 결과에 영향을 준 조건은 ____________________에 남긴다.

## 결과 기록

- [ ] 발견한 막힘을 기록하고 수정 후 같은 경로를 다시 확인했다.
- [ ] 일반 사진 선택, 실제 저장 사진, AI/사람 수정, 포인트·계획·이력 화면을 확인했다.
- [ ] 시간 기준별 측정값과 미검증 항목을 구분했다.

최초 발견: ____________________

수정 후 재확인 일시 / 결과: ____________________

남은 판단 또는 사용성 문제: ____________________

모델 성능 판정은 이 사용성 검수와 별도다. 현재 확정 결과는 train 99.57%로 90% 기준 충족, 고정 test 60%로 70% 기준 미달이다. 상세 화면의 ‘모델 점수(보정 전)’는 모델 전체 정확도나 안전 확률이 아니다. 서버 재시작 후 파일·상태 보존과 의도적인 판독 실패 복구는 담당자의 격리 환경 검증 기록을 함께 확인한다.
