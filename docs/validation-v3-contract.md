# Drone Inspection Platform v3 독립 검증 계약

2026-09-22. 새 사용자 요구에 따른 검증 계약이다. **후보 A의 W01~W11 핵심 흐름은 [후보 A 실행 기록](../records/validation-v3-core-a-2026-09-22.md), 후보 B의 ROI/SHAP 수정 영향과 보존 대조는 [후보 B 실행 기록](../records/validation-v3-roi-b-2026-09-22.md)에 구분했다.** 아래 행렬은 필요한 증거의 기준이며 모든 행의 완료를 뜻하지 않는다. v2 합격은 변경 전 기준이고 v3 합격을 대신하지 않는다. 허브의 `docs/product-v3.md` W01~W16 계약을 기준으로 하며 제품 계약은 허브가 소유한다.

## 1. 범위와 증거 경계

검증 흐름은 **처음 진입 → 생산팀·랙 계획 → 여러 차수 사진 추가 → AI·ROI·설명 → 자동 워크리스트 → 판단·보수 수정 → 계획 완료·취소·복구 가능한 삭제·복원 → 접힌 이력 열기**다. 개별 화면의 기능과 같은 데이터의 전체 흐름을 모두 확인한다.

- QA 소유 파일은 이 문서와 `records/validation-v3-*`다. 제품·모델 코드, 허브 계약과 타 담당 증거는 읽기 전용이다. 기존 서비스·브라우저·DB·볼륨을 임의로 재시작·초기화하지 않는다.
- 후보 인계 전에는 코드·기존 증거를 읽고 검증표만 작성한다. 후보 인계 후 변경 기능과 그 기능이 영향을 주는 핵심 회귀만 실행한다. 통과한 v2 업로드·추론·학습을 준비 명목으로 반복하지 않는다.
- 입력은 승인 demo 또는 승인된 합성 자료를 우선한다. 회사 원본 300장·원본 대응표·비공개 스크린샷은 로컬 전용이다. 목적 선택 UI 제거가 공개 허용 범위를 넓히지는 않는다.
- 고정 test 10장은 UI 표본·ROI 선정·SHAP 배경/설명 표본·모델 튜닝에 쓰지 않는다. 이미 확인한 test 60%는 과거 동결 모델의 결과로 유지하며 새 모델의 미관측 성능처럼 재사용하지 않는다. 새 평가 정책은 모델 담당·허브 계약에 따른다.
- 저장 PASS는 태그·로그·응답 성공만으로 주지 않는다. **같은 ID의 실제 저장값·재조회 API·화면과 원본 바이트**를 연결한다. 메타데이터 변경마다 원본을 반복 다운로드할 필요는 없지만, 최초/최종과 원본·ROI 경로 변경 경계에는 입력→원본 API→객체 해시를 대조한다.
- 기능, 모델 정확도, 설명의 기술적 연결, 설명의 현장 타당성, 에이전트 관측 시간, 실제 사람 검수는 별도 판정한다. SHAP 색상이나 ROI 박스만으로 원인·실제 부식 위치 정확도·안전성·잔여 두께를 증명하지 않는다.

## 3. 요구별 변경·회귀 행렬

## 5. 후보 인계와 실행 순서

1. **후보 고정:** 계약 revision, 웹/API/모델/설명 코드 커밋과 실제 빌드·가중치·전처리 해시, 환경/포트·공개 범위, QA 쓰기 담당·복구 담당·재시작 허용 구간을 받는다. 합의하지 않은 전역 설정 변경은 하지 않는다.
2. **최소 기준 자료:** 기존 계획·포인트·사진·보수·이력·업로드 상태에서 이번 변경과 무관해야 할 ID 집합을 저장한다. 정상·완료보수·수동제외·숨김·과거 미지정 자료를 별도 케이스로 선택하되 QA 소유 복제 환경을 사용한다. 원본300 전체를 새 실험 입력으로 사용하지 않는다.
3. **첫 수직 흐름:** 새 팀 계획에 포인트 없이 승인 사진 한 장을 연결한다. 같은 ID의 원본·AI·ROI/설명·자동 보수·판단 수정·접힌 이력까지 확인한다. ROI/SHAP 계약이 준비되지 않았다면 완료가 아니라 해당 단계 대기로 남긴다.
4. **관계·상태와 실패:** 같은 계획의 추가 차수, 잘못된 팀-랙, 무계획 거절, 계획 완료/취소/숨김/복원, 수동 제외/완료 보수, CAS·늦은 응답을 담당과 조율한 좁은 fixture에서 실행한다. 실패한 하네스를 고친 뒤 실제 저장 성공 여부부터 조회하며 무작정 재전송하지 않는다.
5. **영속·공유·시간:** 원본/이력/관계 전후 대조, 필요한 한 번의 정상 재기동, 같은 고정 URL 확인, 변경된 비동기 경로의 시간 관측을 합친다. 10장 성능·큰 파일·native 선택기 등은 실제 변경 영향과 남은 요구가 있을 때만 재실행한다.
6. **종료·인계:** 요구별 PASS/FAIL/미실행/정책 대기를 구분한다. 기능·모델 정확도·설명 기술검증·현장 효과를 섞지 않는다. 남은 결함·한계·결정과 실제 최종 배포 버전을 허브에 넘긴다. QA가 main 병합·모델 자동 교체·신규 외부 공개를 하지 않는다.

## 6. 영수증 최소 형식

각 결과에 계약/후보 revision, 실행자·시각·도구/브라우저 버전, 전제·입력 크기/해시, 계획·배치·업로드·사진·ROI revision·추론 run·설명 job·보수 ID 대응, 기대/실제값, 원본 API 다운로드·DB/객체 대조, 화면 확인 여부를 남긴다. 실제 모델 호출과 모의 오류/테스트 더블은 구분한다. 실패·복구 단계와 재시도 횟수도 기록한다.

보존 검사는 **불변이어야 할 필드·이력**과 **새 분류/자동 포함 때문에 합의상 달라질 필드·이력**을 미리 나눈다. 새 모델/ROI 결과는 새 revision으로 대응하고 기존 결과를 무음 덮어쓰기하지 않았는지 확인한다. 같은 ID의 API 원본 바이트가 있어야 원본 보존 PASS이며 메타데이터 SHA만 비교한 단계는 그렇게 표시한다.

SHAP은 반환 이미지 존재에 더해 같은 모델 출력에 대한 실제 explainer 계산과 출처를 확인한다. 선택한 방법이 수치 합 관계를 보장/근사하는 경우에만 계약의 출력 단위·허용오차로 검증한다. ROI 변환·원본 역투영을 실제 기하와 대조하며 설명의 부식 전문가 타당성은 별도 미검증으로 남긴다. 설명 그림·원본·background 자료를 공개할 때는 데이터 공개 승인 범위를 다시 적용한다.

공개 기록에는 승인 demo의 기술 결과·집계·버전과 한계만 남긴다. 로컬 상세 경로·원본명/사진·가중치·인증정보·개인 파일 목록·원시 DB는 공개하지 않는다. 이전 실제 OS 선택창 스크린샷을 편의상 새 v3 공개 증거로 복제하지 않는다.
