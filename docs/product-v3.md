# Drone Inspection Platform 확대 수정 계획

2026-09-22 새 사용자 목표다. 기존 v2의 완료 증거는 보존하되 이번 요구의 구현·검증으로 대신하지 않는다. v2와 충돌하는 이름·계획/포인트 필수 여부·워크리스트 수동 등록·추가 모델 개발 정책은 이 문서와 최신 사용자 지시를 우선한다. 이 문서는 실행 전 계약이며 완료 보고가 아니다.

## 목표와 기존 대비 변화

## 초기 업무·데이터 계약

아래는 구현 담당과 맞출 기본 정책이다. API/화면의 실제 계약 확정과 차이는 상태 기록에 남긴다. 사소한 구현 선택 때문에 사용자 승인을 반복해서 요구하지 않는다.

**계획과 랙:** 한 계획은 한 생산팀과 중복 없는 여러 랙으로 구성한다. 랙 범위를 선택해 계획을 저장하며 개별 포인트는 선택사항이다. 기존 point ID와 관계는 삭제하거나 이름으로 새로 추정하지 않는다. 기존 12랙과 원본 300장 관계·좌표를 보존하면서 팀별 30랙 카탈로그로 확장한다. 빈 랙도 계획 대상으로 선택할 수 있다. 새 카탈로그는 가상 구획이며 실측 설비 위치라고 표시하지 않는다.

**여러 차수 업로드:** 신규 사진에는 계획이 필요하다. 계획의 팀과 선택된 랙 범위를 검증하고, 각 파일의 랙 귀속이 명확해야 한다. 기본은 배치의 한 랙을 선택하며 다른 랙 사진은 배치를 나누거나 파일별로 바꿀 수 있게 한다. 여러 랙 선택을 사진의 임의 복제·다중 집계로 해석하지 않는다. 신규 사진은 `planId`, `teamId`, `rackId`를 직접 저장·조회하고 `pointId`는 선택사항이다. 기존 사진은 원래 포인트 관계를 호환 조회하며 계획 수정으로 사진의 기존 귀속을 이동시키지 않는다. 포인트가 없으면 없는 상태로 보존한다. 기존 계획 미지정 사진은 삭제하거나 임의로 계획을 만들지 않고 수정 화면에서 연결할 수 있게 한다. 이름이 같은 파일의 별도 검사 등록과 같은 전송의 재시도를 구분한다.

**계획 상태:** 진행 가능한 계획에 사진을 추가한다. 완료·취소 계획은 기존 사진·판독·보수·이력을 계속 조회하고, ‘재개’ 후 추가할 수 있게 한다. 이미 전송을 시작한 파일의 완료와 계획 종료가 겹치면 저장된 결과를 유실시키지 않도록 API 상태 계약을 정한다. 계획의 팀/랙 수정이 기존 사진 관계를 자동 이동시키지 않게 한다. 사용 중인 범위 축소는 영향받는 기록을 보여주고 명시적인 재연결 또는 기존 범위 보존으로 처리한다.

**삭제와 이력:** 삭제는 복구 가능한 숨김/보관 처리다. 계획 삭제가 사진 원본이나 보수 이력을 연쇄 삭제하지 않는다. 사진 삭제·복원, 보수 항목 숨김·복원, ROI 변경에는 같은 ID 또는 명시된 버전 관계와 수정 이력이 남아야 한다. 기존 두 창의 수정 충돌 방지를 유지한다. 화면에서 이력을 접어도 기록 생성·재조회는 유지한다.

**보수 필요의 자동 반영:** 유효 등급은 사람 수정이 있으면 그 값, 없으면 실제 AI 등급이다. 유효 3~5등급은 업무 검토 대상으로 자동 반영한다. 실제 보수 지시·방법이나 완료 상태를 등급만으로 확정하지 않는다. 포인트가 있는 기존 보수의 계획+포인트 관계는 보존한다. 포인트 없는 새 자료는 사진 ID별 자동 항목을 기본으로 하여 같은 랙 안의 서로 다른 보수 대상이 섞이지 않게 하고, 화면에서 계획/랙별로 묶어 조회한다. 생성·재시도의 idempotency key는 원본 사진과 업무 항목 관계에 묶는다. 다른 계획·다른 랙의 사진을 섞지 않는다. 수동 작업 상태·방법·TA·사유를 재판독으로 덮어쓰지 않는다. 완료된 작업과 새 사진의 추가 검토가 서로 사라지지 않아야 한다. 유효 등급이 1~2로 내려가면 자동 보수 대상에서는 제외하되 항목 ID·작업 상태·방법·이력은 보존한다. 다시 3~5가 되면 같은 항목을 쓰며 명시적 수동 제외를 유지한다. 기존 수동 등록 업무와 자동 판정의 출처를 구분하고 KPI·자동 대상 목록에는 같은 유효 등급 기준을 적용한다. 수동 제외/복원은 이유와 출처를 남기고 단순 새로고침으로 다시 살아나지 않게 한다. ‘관리·TA 워크리스트’의 기본 전체 목록에 모든 대상이 보이며 TA만 보기는 별도 조건이다.

**화면 정리와 데이터 목적:** 업무 사용자에게 `recordPurpose`를 선택시키지 않는다. 새 정상 업무 자료는 서버에서 업무 목적을 부여하며 기존 검증 자료는 보존·격리한다. 발표용/데모용 UI 제거를 원본 삭제나 비공개 자료의 공개 승인으로 해석하지 않는다. 사진·계획·워크리스트·KPI의 백엔드 조건을 일치시키고 페이지 일부 건수를 전체로 쓰지 않는다.

## ROI·SHAP·모델 개선 계약

- 원본의 SHA·크기·방향을 보존한다. ROI는 원본의 정규화된 좌표계, 원본 ID, ROI ID/버전·수정 이력에 연결한다. 회전·확대된 화면의 사각형이 잘못된 픽셀을 판독하지 않도록 EXIF 및 좌표 변환을 검사한다. 전체 사진 AI와 ROI AI는 별도 결과다.
- 설명은 실제 모델·전처리·가중치·대상 등급·설명 기법/배경·입력/ROI 버전에 묶는다. 기여도와 사진 확률·데이터셋 정확도는 다른 값이다. SHAP이 아닌 그림을 SHAP으로 이름 붙이지 않으며, 설명이 실제 부식 원인이나 안전성을 증명한다고 말하지 않는다.
- ROI/설명 결과 수정·취소·재시도와 느린 계산/실패를 구분한다. 잘못된 이전 ROI의 캐시나 다른 사진의 설명을 표시하지 않는다. 원본의 숨김·삭제 뒤 늦게 도착한 결과로 다시 노출되지 않게 한다. 제품·모델 담당이 API 응답과 작업 상태를 맞춘다.
- **M1 진단:** 기존 train/validation의 품질·불균형·오류·전처리와 라벨 한계를 점검한다. 고정 test 내용/결과를 모델 선택용으로 새로 분석하지 않는다.
- **M2 설명 구현:** ROI 입력 및 실제 SHAP 방식의 작동·일관성·지연/메모리를 작은 로컬 표본으로 먼저 확인하고 제품에 연결한다.
- **M3 후보 개선:** train/validation만으로 소규모 후보를 비교한다. crop·증강은 원본 split을 상속하며 독립 데이터로 늘려 세지 않는다. 전체 이미지 라벨을 ROI의 검증된 정답으로 간주하지 않는다. 시드·설정·표본 수·시간·결과·실패를 기록한다.
- **M4 선정과 평가:** validation 결과로 후보를 선정하고 기존 서비스와 비교한다. 새 독립 최종 평가가 필요하면 평가 자료·수집/라벨 기준과 비용을 구체화한다. 기존 test 재사용이나 합격선 하향으로 성능 향상을 만들지 않는다. 새 최종 test 합격은 증거 없이 주장하지 않는다.
- **M5 서비스 연결:** 독립 검토한 호환 후보를 제품·배포와 조율하고 기존 모델과 결과를 복구할 수 있게 전환한다. 검증되지 않은 후보를 운영에 자동 교체하지 않는다. 새 모델 평가 기준·추가 외부 비용/전송·데이터 승격은 기존 판단 경계를 따른다.

이번 사용자는 추가 단계별 모델 개발을 명시 요청했다. 따라서 v2의 ‘추가 모델 실험 없음’은 이번 승인된 로컬 후보 개발을 막는 조건이 아니다. 기존 train231/validation58/test10·중복 제외1, 원본300, 기존 서비스의 train99.57% PASS/test60% FAIL 기록은 그대로 보존한다. 새 후보의 성과를 기존 test 성과로 대신하지 않는다.

## 고정 주소와 전환

현재 익명 quick tunnel 주소는 운영 중인 임시 경로다. 배포 담당은 기존 계정·프로젝트·도메인·지속 가능한 origin 연결을 먼저 확인하고, 고정 제공자 URL 또는 소유 도메인을 확보한다. 같은 호스트 이름이 다시 뜨는지만 아니라 사진 저장·조회·AI·이력까지 통신해야 한다. 프런트 고정 주소 뒤의 API가 다시 임시 주소에 의존해 끊기면 요구 미충족이다.

기존 로그인·승인 범위로 준비 가능한 작업은 진행한다. 새 계정 권한·비용·외부 전송 목적지가 필요하면 실제 가능한 선택지와 필요한 사용자 행동만 구체적으로 요청한다. 원본 300장 전용 환경은 공개 origin으로 연결하지 않는다. 현재 정상 서비스는 새 후보와 고정 경로가 준비되기 전 임의 중단하지 않는다.

## 완료 판정과 보존 검사

각 W01~W16에 실제 실행 버전·화면·API/저장 결과와 한계를 연결한다. 초기 행렬은 `미구현/구현 중/검증 대기/완료/미달/외부 조건 대기`로 기록하며 과거 v2 PASS를 복사하지 않는다.

대표 새 흐름은 ‘첫 진입 → 생산팀 계획/여러 랙 → 포인트 없이 첫 사진 → 같은 계획 추가 사진 → 실제 AI/ROI/SHAP 확인 → 자동 보수 업무 → 수정/완료/취소/삭제/복원 → 접힌 이력 펼쳐 같은 기록 조회’다. 사진과 계획·보수의 ID, 원본 API 다운로드/저장소 SHA, 실제 화면을 대조한다. 전체 업무 약1분은 AI만 기다린 시간과 분리하며 AI와 겹친 다른 업무를 이중 차감하지 않는다. 사람의 사용 시간으로 과장하지 않는다.

변경한 경로의 입력 오류·전송 실패·중복 요청·동시 수정·늦게 끝난 AI/설명·재시작 보존을 검증한다. 모든 검사를 매 수정마다 반복하지 않고 변경 영향과 실제 실패에 맞춰 수행한다. 최종 전환은 운영 백업/동일 버전 기준·후보 통과·새 경로 확인·복구 가능성을 갖추며 DB 초기화나 원본 삭제로 맞추지 않는다. 고정 주소는 실제 외부 접속과 재기동 후 같은 URL의 업무 흐름을 증거로 남긴다.

모델 기능 구현, validation 개선, 독립 최종 평가, 실제 사용자 검수, 향후 운영 유지는 서로 다른 판정이다. 모든 요구의 증거가 준비되기 전 새 확대 목표를 완료 처리하지 않는다. 원본 공개 미승인이나 선택 피드백 부재는 허용된 독립 작업을 멈추는 이유가 아니다.
