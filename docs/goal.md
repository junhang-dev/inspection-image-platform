# 목표·범위·완료 기준

2026-09-21 실제 시작 지시와 후속 사용자 합의를 반영한 기준이다. 초기 준비 범위에 dummy 3D 위치 연결, 검사 계획·캘린더·TA 워크리스트, 보수 업무 상태가 추가되었다. 실측 두께 자료·두께 예측은 후속 사용자 지시로 이번 범위에서 제외한다. 실제 완료 여부는 실행 증거로 확인하며 이 문서만으로 완료를 선언하지 않는다. 회사 배경을 포함한 목표 원문은 공개 제외 로컬 기록으로 보존한다.

## 목표

현업 엔지니어가 검사 사진을 업로드하고 대상·포인트에 연결하면, 실제 AI가 사진 전체의 부식 형상을 1~5등급으로 분류한다. 엔지니어는 필요한 결과를 확인·수정하고 재촬영·관리 포인트·학습 라벨링 후보를 판단하며, 사진과 결과·변경 이력을 다시 조회할 수 있다.

AI 결과를 그대로 사용할 수 있고 사람 검수는 필수 관문이 아니다. 원래 AI 결과와 사람 수정값은 따로 보존하며, 위치를 모르면 추정해 확정하지 않고 **미확인**으로 표시한다. 등급 기준은 [제공된 참고 그림](../ref/%EB%93%B1%EA%B8%89%ED%8C%90%EC%A0%95%EA%B8%B0%EC%A4%80.png)을 따른다. 사용자 요청에 따라 3~5등급은 **보수 필요(숫자 등급)**, 1~2등급은 **보수 불필요(숫자 등급)**로 표시한다. 이는 시각적 분류이며 설비 안전성·잔여 두께·최종 보수 지시를 대신하지 않는다. 보수 검토·진행·완료는 별도로 기록하는 업무 상태다.

## 이번 범위

- 사진 묶음 업로드, 설비번호·랙·검사 포인트 입력과 dummy 3D 위치 연결, 실제 AI 판독, 선택적 등급 수정, 사진·결과·이력 조회. 가상 배치와 실제 측량 위치를 구분한다.
- 재촬영 필요 표시와 사유 기록, 관리 포인트의 워크리스트 포함·해제, 사진의 학습 라벨링 후보 지정·해제. 각 목록을 조회하고 변경 이력을 보존한다.
- 포인트별 보수 검토·진행·완료 상태와 사유 기록, 검사 계획·캘린더에서 TA 워크리스트 반영까지 연결한다.
- 사진 전체 등급 분류 모델의 사전 튜닝과 제품의 실제 추론 연결. 기존 train/validation/test 분리를 유지하고 파일명 정답으로 예측을 대신하지 않는다.
- 원본 300장과 부가 자료는 로컬에 보존한다. 공개 저장소에는 승인된 참고 그림 6개와 train에서 복제한 시연 사진 5개만 포함한다. demo 복제본은 학습 데이터에 추가 집계하지 않는다.
- 학습·평가 사진은 제공된 원본과 기존 분리만 사용하며 외부 사진을 추가하지 않는다. 공개 사전학습 가중치 사용과 새 사진 데이터 추가를 구분한다.
- Next.js, Docker Compose, MySQL, MinIO, Vercel을 기본 방향으로 삼는다. Jun의 Mac 한 대에서 원본·DB·모델을 보존·처리한다. Docker Compose로 시작·종료·재시작을 통일하고 실제 구성과 데이터 보존을 검증한다. 사용자가 승인한 다른 호스팅은 승인 목적지·전송 범위·시점을 기록하고 적용한다.
- 임시 URL로 팀원·심사위원이 접속하며 심사 종료까지 서버·터널·전원·네트워크를 유지한다. 작은 모델·소량 실험부터 실행 시간과 메모리를 확인해 확대하고, 자원이 부족하면 규모를 조정한다.

**가능하면 구현:** Label Studio 연결과 재학습 흐름. 구현 여부·제약을 보고한다. **이번 제외:** 실측 두께 자료·두께 예측, 실제 드론 dock 자동 촬영·업로드, 실제 설비 3D 디지털 트윈, AWS S3 전환. 별도 서버·외부 GPU·클라우드 비용 확대는 합의되지 않았다. 참고 그림 속 모든 시스템을 필수 요구로 확대하지 않는다.

## 모델 평가

기존 분리는 train 231장 / validation 58장 / 고정 test 10장이다. 원본 300장 중 동일 내용의 중복 1장은 기존 목록에서 제외돼 있으며 이 분리를 다시 만들지 않는다. 분리 목록과 전체 원본은 Jun의 로컬 관리 자료다.

초기 train/validation 결과를 본 뒤, 최종 test를 열기 전에 사용자가 **train 정확도 90% 이상, 고정 test 정확도 70% 이상(10장 중 7장 이상)**으로 합격선을 정했다. 정확도는 사진 전체 1~5등급의 정답과 예측이 정확히 일치한 비율이다. 재현율·혼동행렬 등은 추가 보고하되 별도 미승인 합격 조건으로 사용하지 않는다. 고정 test 10장은 샘플 선정·튜닝에 사용하지 않으며 최종 평가 모델·전처리 버전과 사진별 실제 결과를 기록한다. 기능 완료와 모델 성능 완료는 각각 확인한다.

최종 모델과 전처리 버전을 고정한 뒤 평가하며, 최종 test 결과를 보고 튜닝하거나 합격선을 낮추지 않는다. 학습·검증 개선 시도를 10회 이상 했는데도 더 이상 개선되지 않으면 가장 나은 모델을 실제 서비스에 연결하되, 성능 미달·한계를 숨기지 않는다. 연결 성공을 성능 합격으로 간주하지 않는다.

## 완료 기준

1. 사진 묶음을 업로드하고 각 원본·설비번호·랙·포인트를 재조회하며 dummy 3D 위치 매핑을 확인할 수 있다. 모르는 위치는 미확인으로 남는다.
2. 고정 test 10장에 실제 모델을 실행하고 모델·전처리 버전·사진별 정답과 예측·정확도를 남긴다. 평가에 사용한 동일 모델과 전처리 버전을 제품 실제 추론에 연결했는지 확인한다. 합의한 성능 기준의 충족 여부를 기능 동작과 별도로 보고한다.
3. 필요한 사진의 등급을 수정하거나 AI 결과를 그대로 사용하고, 숫자 등급과 보수 분류를 확인한다. 재촬영 표시·사유, 워크리스트 포함·해제, 라벨링 후보 지정·해제와 각 목록 조회를 수행할 수 있다. 포인트별 보수 검토·진행·완료와 사유를 기록하고 검사 계획·캘린더·TA 워크리스트로 연결한다.
4. 수정 전후 값·수정자·시각·사유를 확인하고, 새로고침과 서비스 재시작 뒤에도 사진·결과·후속 판단·변경 이력이 보존된다.
5. 사진이 없는 상태·잘못된 파일·판독 실패를 구분하고 다음 행동을 안내한다. 실패를 성공으로 표시하지 않는다.
6. 비개발자 팀원 한 명이 전체 흐름을 수행하고, 막힌 부분의 수정 후 재확인까지 마친다. 실행한 검사·사용 버전·남은 한계·실제 제출 화면이 일치한다.
7. 내비게이션·토글·설명·상태에 한국어 용어와 디자인을 일관되게 적용하고 실제 화면을 검수한다.
8. 검사 계획은 30초 이내, 사진 10장 업로드는 30초 이내, 사진 10장 추론은 백그라운드에서 3분 이내에 수행한다. 대시보드·조회·리포트는 수초 이내이며 사용자 작업을 추론이 막지 않는다. 사용자 요청의 '모든 과정 1분 내외'에 대해서는 능동 조작과 비동기 추론 시간을 분리해 측정한다. 1분 기준의 적용 범위는 잠정 해석이며 사용자 검수에서 확정한다. 확인 전 이 해석만으로 합격을 선언하지 않는다. 측정 환경·파일 수/크기·시작/종료 정의·실제 시간을 기록한다.
9. 외부 URL에서 실제 접속과 업무 흐름을 확인하고, 심사 종료까지 필요한 서버·터널·전원·네트워크 조건을 인계한다. 로컬 실행 성공과 외부 접속 성공을 구분한다.
10. 실제 이미지가 업로드되어 백엔드·객체 저장소에 저장되고, 백엔드에서 다시 조회한 파일이 원본과 같은지 확인한다. 이미지·포인트·객체의 안정된 식별자, 파일 크기·해시 대조와 실제 사진 렌더링을 증거로 남긴다. 파일명만 같거나 응답 코드만 정상인 것을 저장 성공으로 처리하지 않는다.
11. 사용자가 직접 확인할 수 있도록 실제 업로드, 저장된 사진 재조회, AI 결과와 수정값, 포인트 연결·후속 상태·이력 화면의 스크린샷을 남긴다. 테스트 로그 작성만으로 PASS를 선언하지 않는다. 각 PASS에는 실제 파일·백엔드 조회·화면 증거가 대응해야 하며 미실행·실패는 구분한다. 공개 가능한 증거에는 승인 demo만 사용하고 민감 원본·로컬 정보가 포함되지 않도록 확인한다.
12. 데이터 확인 PASS는 기존 분리의 수량·원본 대응·중복 및 누출 검사·demo 중복 집계 방지 등 검증한 범위를 명시한다. 구조·파일 일치 검증을 등급 라벨의 현장 정답성 보증으로 확대하지 않는다.

## 팀 역할

| 담당 | 역할 |
|---|---|
| Jun | 개발·제품 코드 통합 총괄, 최종 제출 |
| 아이디어를 발의한 현업 엔지니어 | 업무 기준, 기존 시도 경험, 발표 |
| 동료 엔지니어 | 사용자 검수, 녹화·제출 지원 |

완료 기준을 충족하면 새 기능을 늘리지 않고 팀 검수로 넘긴다. 실제 행사 시작 시각·시작 커밋·사용한 목표와 수행 증거는 [records/](../records/)에 기록한다.

허브는 우선순위·진행·결과 회수·사람 판단을 관리하고 담당 작업이 구현한다. 같은 파일 편집과 Git 작성은 각각 한 명씩 맡는다. 이 허브의 30분 관제 예약은 정상 진행을 중복 실행하지 않고 실패 복구·후속 작업을 조율한다. 자동 pull·commit·push 예약은 만들지 않는다. 원문·로컬 경로·민감 결과는 공개 제외 기록으로 보존한다. 기능 동작·부식 분류 성능·사용자 검수를 각각 완료/미달/미검증으로 보고한다.
