# Git 작업 안내

## 기본 개념과 담당

Git은 파일의 변경 이력을 로컬에 저장합니다. **커밋**은 설명이 붙은 저장 시점이고, **GitHub**는 이 기록을 원격에 보관하고 팀과 공유하는 곳입니다.

- 시작 브랜치: `main`.
- Git/GitHub 설정·기록 방식 준비: Git 준비 담당.
- 이후 코드·문서 기록: 해당 파일을 작성하는 제품 담당. 완료한 작업이나 안전한 중간 저장 시점에 기록합니다.
- 허브: 할 일·역할 분담·결과 요약을 관리합니다. 작성 중인 파일이나 index를 대신 커밋하지 않습니다.
- 같은 저장소에서 여러 작업이 동시에 `git add`·`git commit`을 실행하지 않습니다.
- 현재 자동 예약은 없습니다. 필요성·범위·시점을 정한 뒤 별도로 구성합니다.

## 기록할 수 있는 파일

초기 허용 파일은 `.gitignore`, `.dockerignore`, `README.md`, `docs/GIT_WORKFLOW.md`, `docs/STORAGE.md`, `docs/DECISION_PROCESS.md`입니다. 이후 구현 코드·테스트·공유 가능한 문서·의존성 선언 파일은 내용을 검토하고 경로를 명시해 추가합니다.

다음은 기본 제외 대상입니다.

- `image/` 전체: 회사 사진과 이 폴더에 만드는 학습 목록·분리 목록·검토 자료.
- 원본 이미지 및 기존 참고 그림, 회사 파일명·포인트·로컬 경로가 담긴 자료.
- 로컬 데이터·업로드·DB·실행 로그, 이미지가 포함될 수 있는 노트북·문서·영상·압축 파일.
- 모델 가중치·학습 결과, 비밀·인증 파일, 설치된 의존성·캐시·빌드 결과.
- MinIO·MySQL의 실제 저장 파일과 볼륨 데이터. Compose 설정과 실제 데이터의 기록 범위를 구분합니다.

`.gitignore`는 파일의 **이름과 경로**로 제외합니다. 문서나 코드 본문에 붙여 넣은 회사 정보까지 검사하지는 못합니다. 이미 커밋된 파일도 자동으로 제거하지 않습니다. 가짜 예제나 공개 가능한 자산이 필요하면 내용을 확인한 뒤 특정 파일에만 예외를 추가합니다. `git add -f`로 우회하지 않습니다.

## 한 작업을 기록하는 순서

제품 저장소 폴더에서 실행합니다. `git add`는 커밋할 파일을 골라 올리는 단계이며, 아래 경로는 문서 수정의 예입니다.

```sh
git status --short
git diff
git add -- README.md docs/GIT_WORKFLOW.md
git diff --cached --stat
git diff --cached
git commit -m "docs: clarify setup instructions"
git status --short
git log -1 --oneline
```

파일 전체를 일괄 추가하는 `git add .` 대신 수정·검토한 경로를 적습니다. staged 목록에 사진·비밀·학습 목록이 보이면 커밋을 멈추고 담당자에게 알립니다. 인증 파일의 내용을 출력하거나 공유하지 않습니다.

완료한 작업에는 수행한 검증을 기록합니다. 미완성 상태의 안전한 중간 기록은 커밋 설명에 `checkpoint:`와 미검증 항목을 남깁니다. 변경이 없으면 빈 커밋을 만들지 않습니다.

## 기록 확인과 원격 백업

```sh
git show --stat HEAD
git show HEAD:README.md
```

위 명령은 저장한 기록을 읽기만 하므로 현재 파일을 덮어쓰지 않습니다. 복구가 필요하면 먼저 대상 커밋과 보존할 변경을 확인합니다. 자동 초기화, 강제 push, 작성 중인 worktree 삭제는 사용하지 않습니다.

공개 원격 대상은 `https://github.com/junhang-dev/inspection-image-platform`입니다. 현재 파일뿐 아니라 올릴 커밋 전체의 포함 자료를 검토합니다. 회사 자료는 비공개 저장소에도 올리지 않습니다. 실제 push 후 로컬 커밋과 원격 커밋이 같은지 확인해야 원격 백업 완료입니다.

커밋 작성자 이메일은 이 저장소에서 GitHub의 `noreply` 주소를 사용합니다. 개인 이메일이 포함된 미게시 기록은 공개 전 확인합니다. 다른 저장소의 전역 작성자 설정은 바꾸지 않습니다.

로컬 커밋만으로는 컴퓨터 고장에 대비한 외부 백업이 되지 않습니다. Git에서 제외한 자료는 회사의 허용된 별도 보관 방식으로 관리합니다.
