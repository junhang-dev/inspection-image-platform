# Drone Inspection Platform

검사 사진을 계획·생산팀·파이프랙에 연결하고, AI 판독과 보수 후속 업무를 관리하는 웹 서비스입니다.

- 서비스: [Drone Inspection Platform](https://drone-inspection-g10.dlwnsgod2761.workers.dev)
- 소스 코드: [GitHub 저장소](https://github.com/junhang-dev/inspection-image-platform)

## 사용 방법

1. **검사 계획**에서 생산팀과 검사할 랙을 선택해 계획을 만듭니다. 개별 포인트는 나중에 연결해도 됩니다.
2. **사진 · 판독**에서 계획과 랙을 선택하고 사진을 추가합니다. 같은 계획에 사진을 여러 차례 추가할 수 있습니다. 사진 목록에서는 계획과 판독 상태로 필요한 사진을 찾습니다.
3. 사진을 열어 **AI 판독 상태와 현재 분류**를 확인합니다. 사람 판정을 바꾸거나 재촬영을 지정할 때는 사유를 적어 저장합니다. 학습 라벨링 후보 지정은 별도 동작입니다. 원래 AI 결과와 사람의 수정값은 따로 보존됩니다.
4. 보수가 필요한 사진은 **보수 관리** 목록에 자동으로 나타납니다. 각 사진의 작업 방법, 진행 상태, TA 작업 포함 여부를 기록합니다. **워크리스트 관리**에서는 아직 묶이지 않은 TA 사진을 두 장 이상 선택해 이름이 있는 작업 묶음을 만듭니다. 묶음의 진행 현황은 사진별 상태를 모아 보여주며, 실제 기록은 각 사진에서 따로 관리합니다.
5. **라벨링 후보**에서 지정한 사진을 확인하고, 각 상세 화면의 변경 이력에서 판단 과정을 조회합니다.

## 현재 상태와 다음 작업

| 현재 상태 | 다음 작업 |
| --- | --- |
| **화면과 업무 흐름:** 검사 계획 → 사진 · 판독 → 보수 관리 → TA 작업·라벨링 후보 흐름의 1차 재설계를 마쳤습니다. | 실제 현업 사용자 검증과 업무 매뉴얼을 진행합니다. |
| **배포:** 고정 HTTPS 주소가 Cloudflare를 거쳐 Mac의 공유 웹·API에 연결됩니다. | Mac과 로컬 저장소에 의존하지 않는 상시 운영 방식을 확정합니다. |
| **로그인과 권한:** 로그인 화면은 안내 단계입니다. | 사용자 역할, 관리자만 가능한 작업, 사진 공개 범위와 접근 제어를 설계·구현합니다. |
| **AI 판독:** 기존 동결 모델의 서비스 연결과 결과 저장 경로가 있습니다. 과거 고정 평가 결과는 [평가 기록](records/model-final-evaluation.md)에 있습니다. | 모델의 학습·전처리·가중치 연결 관계를 운영 관점에서 더 파악하고, 오류 분석과 개선 실험을 이어갑니다. |
| **ROI·SHAP:** 코드와 제한된 통합 검증 기록이 있습니다. 화면에 기능이 보여도 전체 업무 완료를 뜻하지 않습니다. | 운영 연결, 설명의 사용성, 권한과 현업 적합성을 더 확인합니다. |
| **Label Studio:** 제품에서는 라벨링 후보를 지정·조회할 수 있습니다. 별도 [로컬 Label Studio 연계 코드](labeling/README.md)는 있으나, 현재 제품 서비스와는 아직 연결되지 않았습니다. | 로컬 Label Studio와 제품 후보의 연결 범위를 정하고, 가져오기·라벨 작성·내보내기의 전체 흐름을 운영 환경에서 검증합니다. |
| **운영 인수:** 실행·배포·복구 기록이 있습니다. | 다른 담당자가 백업·복구까지 재현할 수 있는 절차와 장기 운영 환경을 정리합니다. |

현재 모델의 식별자와 이전 실험 결과는 [모델 운영 기록](records/model-operations.md)과 [평가 기록](records/model-final-evaluation.md)을 참고하세요. 과거 고정 test 결과를 현재 운영 상태나 새로운 개선 성과로 해석하지 않습니다.

## 저장소와 실행 구조

| 경로 | 역할 |
| --- | --- |
| `src/app/`, `src/components/`, `src/lib/` | Next.js 화면, 업무 화면 구성요소, API 호출과 표시 규칙 |
| `server/` | Express API, 계획·사진·판독·보수 데이터와 업무 규칙 |
| `ml/` | Python 이미지 판독 모델, ROI·SHAP 서비스와 검증 코드 |
| `labeling/` | 로컬 Label Studio 연계·재학습 관리 코드. 현재 제품 서비스에는 연결되지 않음 |
| `scripts/`, `compose*.yaml` | 실행·저장소 준비·검증 도구와 로컬 인프라 정의 |
| `docs/`, `records/` | 제품 기준·운영 방법과 시점별 실행·검증 기록 |

브라우저 요청은 Next.js 웹을 거쳐 Express API로 갑니다. API는 **MySQL에 계획·판독·보수·이력**, **MinIO에 사진 원본**을 저장하고, 별도 **Python 모델 서비스**에 판독을 요청합니다. 고정 서비스 주소는 Cloudflare Worker·Tunnel을 통해 Mac의 공유 웹으로 연결됩니다. GitHub에는 코드와 문서만 두며, DB·원본 사진·모델 가중치·비밀 설정은 포함하지 않습니다. 개인 개발 환경과 공유 운영 환경은 데이터와 포트를 분리합니다.

## 로컬 개발

필요한 Node.js·npm 버전과 개인 전용 데이터 설정은 [개발·데이터 안내](docs/private-import.md)를 따릅니다. 아래 명령은 전용 설정·DB·MinIO가 준비된 개발 환경에서 사용합니다.

```sh
npm ci
npm run dev:private
```

개발 웹은 `http://127.0.0.1:3100`, 전용 API는 `http://127.0.0.1:4100`에서 실행합니다. 공유 운영 웹/API는 `3000/4000`입니다. 운영 설정으로 개발 서버를 실행하지 마세요.

변경한 코드의 기본 확인 명령은 다음과 같습니다.

```sh
npm run typecheck
npm test
npm run build
```

## 배포와 데이터 관리

[배포 안내](docs/deployment-v3.md)에 고정 주소의 연결과 릴리스 전환·복구 조건이 있습니다. [실행 계약](docs/product-v3-runtime.md)은 계획, 업로드, 보수와 ROI·SHAP의 데이터 규칙을 설명합니다. 실제 운영 설정과 자격 정보, DB·사진·모델 파일은 Git에서 제외한 로컬 경로에 둡니다. 배포 전에는 진행 중인 업로드와 판독 작업을 확인하고, DB·사진 객체와 이전 릴리스를 복구할 수 있게 보존합니다. 배포 후에는 고정 주소에서 웹·API·사진 조회·판독 상태를 각각 확인합니다.

최신 제품 범위는 [제품 요구사항](docs/product-v3.md), 실제 검증 범위와 한계는 [검증 기록](records/)을 참고하세요.
